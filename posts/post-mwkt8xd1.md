## 学习心法

1. **每层只问三句**：这层管什么？数据单位（PDU）叫什么？靠什么协议？
2. **封装/解封是总纲**：发送方逐层加"信封"，接收方逐层拆——抓包时看到的一切嵌套由此而来；
3. **两个地址两个号**：MAC（出厂身份证，链路层）、IP（门牌地址，网络层）、端口（房间号，传输层）——三者分工贯穿全书。

# n01 分层模型：网络的宪法

> 本章目标：理解"为什么分层"、五层模型各层职责、封装/解封全过程。分层是全书的目录——背下它，后面的章就有了位置感。

---

## 1.1 为什么需要分层

📌 **比喻**：寄快递。你（应用层）只需把东西装箱写地址；快递公司（传输层）管"保证送到"；分拣中心（网络层）管"走哪条干线"；货车司机（链路层）管"这一段路开稳"；公路（物理层）承载一切。**你不需要懂干线调度，快递公司不需要懂路况维护——各司其职、接口固定**。

📐 **定义**：**分层是把网络通信的复杂功能切分成若干层，每层向上提供服务、向下调用服务，层间接口标准化**。收益：**解耦**（每层独立演进：以太网换了光纤，你上网的方式没变）、**标准化**（不同厂商互通）、**故障定位**（逐层排查）。

## 1.2 五层模型（本书主线）与 OSI 七层

| 层       | 单位（PDU）    | 职责                          | 代表协议/设备         | OSI 对应              |
| -------- | -------------- | ----------------------------- | --------------------- | --------------------- |
| 5 应用层 | 消息 message   | 为应用服务                    | HTTP/HTTPS、DNS、SMTP | 应用/表示/会话（7~5） |
| 4 传输层 | **段 segment** | 进程到进程、端口、可靠/不可靠 | TCP、UDP              | 传输（4）             |
| 3 网络层 | **包 packet**  | 主机到主机、IP 寻址路由       | IP、ICMP、路由器      | 网络（3）             |
| 2 链路层 | **帧 frame**   | 相邻节点、MAC、差错检测       | 以太网、Wi-Fi、交换机 | 数据链路+物理（2~1）  |
| 1 物理层 | 比特           | 电/光信号传输                 | 网线、光纤、集线器    | （并入）              |

**OSI 七层**是理论参考模型（学院派、完整），**TCP/IP 四层/五层**是实际使用的模型（工程派）——考试与工程沟通用五层，OSI 名词（表示层/会话层）作了解。

**记忆锚点（两个地址两个号）**：MAC 地址 = 身份证（出厂焊死，链路层寻址）；IP 地址 = 门牌（可搬迁，网络层寻址）；端口号 = 房间号（找到主机后找具体进程）。

## 1.3 封装与解封：全程总纲

📌 **比喻**：信装信封、信封装箱、箱子装车——每层给数据套一层"信头"写明本层信息；接收方倒序拆封。

```
发送方（自上而下封装）：
应用层：[ HTTP 报文 ]
传输层：[ TCP 头 | 数据 ]                    ← 段
网络层：[ IP 头 | TCP 头 | 数据 ]             ← 包
链路层：[ 帧头 | IP 包 | 帧尾(CRC校验) ]      ← 帧
物理层：变成比特流发出去

接收方（自下而上解封）：逐层剥头 → 交给对应上层协议
```

**每一层的头都写给"对端同层"看**：TCP 头被对端的 TCP 层拆，IP 头被沿途路由器（网络层设备）拆——这就是"层间接口固定"的物理体现。抓包软件 Wireshark 看到的嵌套结构正是这个洋葱。

## 1.4 性能指标速查

- **带宽**：信道的最大速率（bit/s）——"路宽"；
- **时延四件套**：发送时延（数据量/带宽，"装车时间"）+ 传播时延（距离/速度，"路上时间"）+ 处理时延 + 排队时延；**大文件瓶颈在带宽，小游戏瓶颈在传播+排队（延迟）**；
- **往返 RTT**：一来一回的时间（Ping 看到的）；
- **丢包率**：可靠传输压力的指示器。

## 易错点清单

1. 交换机（链路层，看 MAC）与路由器（网络层，看 IP）混用——"二层/三层设备"；
2. 带宽 ≠ 延迟：千兆带宽不改善 Ping 值（延迟是传播+排队问题）；
3. 集线器（物理层，广播傻放大）在考古题外已绝迹——现代全交换机。

## 自测题

1. 一台主机发送网页数据，写出封装后的完整洋葱结构。（帧头|IP头|TCP头|HTTP报文|帧尾）
2. OSI 七层中"表示层"干什么？在五层模型里归谁？（编码/加密/压缩——并入应用层）
3. 路由器工作在第几层、依据什么转发？（网络层，依据目的 IP）

# n02 物理层与链路层：MAC、以太网、ARP

> 本章目标：数据在同一片"局域网"里怎么走——比特变信号、MAC 寻址、以太网帧、交换机转发、ARP 问路。

---

## 2.1 物理层：比特变信号

📌 **比喻**：物理层是"声带与耳朵"——把 0/1 变成电/光/无线电波，对端再变回来。

📐 **要点**：

- **信号编码**：多少电压/光强代表 0 和 1（曼彻斯特编码等，细节了解即可）；
- **传输媒体**：双绞线（网线，百米内）、光纤（远距高速）、无线（Wi-Fi/蜂窝）；
- **信道极限**：奈奎斯特/香农公式——带宽与信噪比决定速率上限（工程上"网线不好会丢包降速"的原理）；
- **设备**：中继器/集线器（放大转发，物理层"傻"设备，现代已淘汰）。

## 2.2 链路层：相邻节点的一段路

📌 **比喻**：同城快递的一段运输——不需要懂全国路线（那是网络层的事），只管"把包裹交给下一站，并确认没送坏"。

📐 **定义**：链路层负责**相邻两节点之间**的帧传输：封装成帧、**MAC 寻址**、差错检测（CRC 校验：帧尾附校验码，坏了就丢）、流量协调。现代以太网（交换式）**不再需要 CSMA/CD 碰撞检测**（全双工、交换机隔离冲突域），但考试仍要求掌握其思想（载波侦听+冲突退避——历史演进的基石）。

### MAC 地址

- 48 位（6 字节），形如 `AA:BB:CC:DD:EE:FF`，前 3 字节厂商号、后 3 字节序列号——**出厂焊死、全球唯一（理论）**；
- 帧头：`[目的 MAC | 源 MAC | 类型 | 数据 | CRC]`；
- 特殊地址全 `FF` = **广播**（发给全网所有人）。

### 以太网帧与 MTU

```
[前导码] [目的MAC 6B] [源MAC 6B] [类型 2B] [数据 46~1500B] [FCS 4B]
```

**MTU = 1500 字节**：IP 包超过它就要**分片**（网络层的事，n03）——MTU 是跨层联动的典型约束。

## 2.3 交换机：会看 MAC 的智能分拣

📌 **比喻**：**智能快递分拣台**——记一张"MAC 地址 → 出口"的表（CAM 表），包裹来了看目的 MAC，精准丢给对应出口；没记录就广播给所有口（洪泛），谁应答就学谁。

📐 **工作流程**：收到帧 → 查 MAC 表 → 有表项 → 只从对应端口转发；无表项 → **洪泛**（泛洪给除入口外所有端口）→ 目标回包时**学习**（源 MAC ↔ 端口写入表）。对照：**集线器**无脑广播（所有口都复制，带宽共享、冲突不断）已被淘汰。

## 2.4 ARP：IP→MAC 的问路人

📌 **比喻**：你知道收件人**门牌号**（IP），但货车司机要的是**人脸**（MAC）。于是喊一嗓子："谁是 192.168.1.5？"（ARP 请求广播），本人应答"我是，MAC 是 xx"（ARP 应答），司机记进小本本（ARP 缓存）。

📐 **流程**：

```
① 主机 A 要发给同网段的 B（IP 已知）→ 查 ARP 缓存 → 无记录
② A 广播 ARP 请求："谁是 192.168.1.5？告诉 192.168.1.10"
③ B 单播 ARP 应答："我是，MAC=BB"；A 写入缓存（有生存期，几分钟过期）
④ 帧以 B 的 MAC 为目的地址发出
```

**跨网段的关键**：目标不同网段时，ARP 问的不是对方主机，而是**网关（默认路由器）的 MAC**——"包裹交给快递站点"，站点再层层接力（n03 路由）。ARP 欺骗（伪造应答冒充网关）是局域网攻击经典——对应防御：静态绑定、动态 ARP 检测（安全专题式回收）。

## 易错点清单

1. MAC 地址跨网段传输会**变**（每经过一个路由器，源/目的 MAC 换成这段链路的），IP 不变——帧是"每段路的新信封"，IP 包是"里面的信"；
2. 交换机转发用 MAC 表、路由器转发用路由表——设备与依据配对；
3. ARP 是广播、ARP 应答是单播。

## 自测题

1. 主机 A（192.168.1.10/24）发数据给 192.168.2.5，ARP 请求谁？（默认网关的 MAC——跨网段交给站点接力）
2. 交换机收到目的 MAC 未知的帧怎么办？（洪泛：除入口外所有端口转发，同时学习源 MAC）
3. MTU 1500 意味着 IP 层超过多少要分片？（IP 包 > 1500 - 各层头 ≈ 1480 数据时）

# n03 网络层（IP）：门牌、分区与导航

> 本章目标：IP 地址体系（IPv4/子网/NAT）、路由转发、ICMP。网络层是"从源头到目的、跨过千山万水"的那层。

---

## 3.1 IPv4 地址：门牌与分区

📌 **比喻**：地址 `192.168.1.5/24` 像一个详细门牌——**前半是小区名（网络号），后半是楼栋门牌（主机号）**；`/24` 是"前 24 位是小区名"的说明。

📐 **定义**：IPv4 地址 32 位（4 字节，点分十进制 `x.x.x.x`），由**网络号 + 主机号**组成，**子网掩码**（如 255.255.255.0 = /24）划定分界线。判定"同一小区（网段）"：**两 IP 分别 AND 掩码，结果相同则在同一子网**（同小区直接喊话 ARP；不同小区交给网关，n02 呼应）。

地址分类与特殊地址：

| 类型         | 范围                        | 用途                                   |
| ------------ | --------------------------- | -------------------------------------- |
| A / B / C 类 | 传统分类（历史）            | 按首位/前缀分大小                      |
| **私网地址** | 10/8、172.16/12、192.168/16 | 内网使用，**不可公网路由**（配合 NAT） |
| 回环         | 127.0.0.1（localhost）      | 本机自己                               |
| 广播         | 主机号全 1                  | 发给本网段所有主机                     |
| **IPv6**     | 128 位，`2001:db8::1` 形式  | 地址枯竭的终极方案（4→16 字节）        |

## 3.2 子网划分与 CIDR

📌 **比喻**：一个小区把车位再划区——**借主机号的高位当子网号**，`/24` 可细分为两个 `/25`（各 126 台可用主机）。

📐 **CIDR（无类域间路由）**：掩码不再受 A/B/C 类约束，用 `/n` 任意划分——`192.168.1.0/26` → 64 个地址、可用 62（**去掉网络地址全 0 与广播地址全 1**）。计算三件套：网络地址（IP AND 掩码）、广播地址（网络地址 + 主机位全 1）、可用主机数（2^主机位 − 2）。这是考试必考的手算题，对照书练 10 道。

## 3.3 路由：导航逐跳转发

📌 **比喻**：导航每一步只告诉你"**下一站**去哪"——快递从北京到上海，北京分拣中心只管"发往下一枢纽"，不知全程。

📐 **定义**：**路由器依据路由表按目的 IP 选下一跳**；路由表条目 = `目的网段/掩码 → 下一跳/接口`。**最长前缀匹配**：多个条目都命中时选掩码最长（最具体）的——`10.0.0.0/8` 与 `10.1.0.0/16` 同时匹配时走 /16。默认路由 `0.0.0.0/0` 兜底（"其他全走网关"）。

**IP 包在途中的变化**（n02 呼应）：每过一个路由器——**TTL 减 1（减到 0 丢弃，防环路打转）**、源/目的 MAC 换成本段链路的、**源/目的 IP 不变**（信封里的信始终如一）。

**路由协议**（路由表怎么来）：内部网关 **RIP**（跳数，距离向量）、**OSPF**（链路状态 + Dijkstra——数据结构卷 d05 回收！）、外部 **BGP**（自治域之间的政治经济型选路）。

### IPv6：地址枯竭的终极方案

IPv4 只有 43 亿地址，NAT 只是续命——**IPv6（128 位）是正解**：

- 地址写法：8 组 16 位十六进制，`2001:db8::1`（连续 0 可用 `::` 压缩一次）；
- 数量：2¹²⁸ ≈ 3.4×10³⁸——"地球上每粒沙子都能分到"级别；
- 不再需要 NAT（每设备真·公网地址）、**无广播**（改用组播/任播）、**自动配置 SLAAC**（插网线自己算地址，无 DHCP 也能通）、报文头简化（固定 40 字节，路由器处理更快）；
- 迁移：双栈（同时跑 v4/v6）、隧道（v6 over v4）——过渡期技术的现实折中。

考试要点：IPv6 地址 128 位、`::` 只能出现一次、无广播/无校验和（交给链路层与传输层）、ICMPv6 取代 ARP（邻居发现 ND）。

## 3.4 NAT：一家共用一个公网门牌

📌 **比喻**：公司前台（NAT 路由器）——全公司（私网）对外只报前台号码（公网 IP）；外面寄来的件前台按**桌号标签**转交到工位。

📐 **定义**：**NAT（网络地址转换）**在私网与公网边界改写 IP/端口：内网主机发包时，源地址换成公网 IP + 随机端口，并记录映射表；回包按表反译送到对应内网主机。价值：**公网 IPv4 不够用**（43 亿 < 世界设备数）的最主流缓解方案。代价：外网无法主动访问内网主机（需端口映射/打洞——P2P 与游戏联机的技术难点）。

## 3.5 ICMP 与 ping

**ICMP**（互联网控制消息协议）是 IP 的"哨兵"：**ping** 用回显请求/应答测连通性与 RTT；**TTL 超时**消息支撑 `traceroute`（沿途路由器逐个现形）；目的不可达告警。它也是攻击素材（ICMP 洪水、smurf），防火墙常限速处理。

## 自测题

1. 判断 192.168.1.100/26 与 192.168.1.66/26 是否同网段？（AND 掩码 255.255.255.192：100→64，66→64——同网段 192.168.1.64）
2. /26 的可用主机数？（2⁶ − 2 = 62）
3. IP 包经过路由器时哪些字段变、哪些不变？（TTL−1、MAC 换段；源目的 IP 不变——NAT 除外）
4. 私网地址三段是什么？（10/8、172.16/12、192.168/16）

# n04 传输层：TCP 与 UDP

> 本章目标：传输层解决"进程到进程"（端口）与"可靠还是快"（TCP vs UDP）。**本章是全卷最重的一章**——三次握手、四次挥手、滑动窗口、拥塞控制是考试与面试的双料顶流。

---

## 4.1 端口：找到主机上的具体进程

📌 **比喻**：IP 找到大楼（主机），**端口 = 房间号**——快递上写"808 房"才能送到具体业务。

📐 **定义**：端口号 16 位（0~65535），**IP + 端口 = 套接字（socket）地址**。知名端口：HTTP 80、HTTPS 443、DNS 53、SSH 22、FTP 21。临时端口（>49152）由客户端随机取——"你访问网站"时你的浏览器也开着一个临时端口收数据。

## 4.2 UDP vs TCP：寄明信片 vs 打电话

|           | **UDP**                  | **TCP**                            |
| --------- | ------------------------ | ---------------------------------- |
| 比喻      | 寄明信片：写完就扔邮筒   | 打电话：先"喂喂听得到吗"，逐句确认 |
| 连接      | 无连接                   | 面向连接（三次握手）               |
| 可靠性    | 尽力而为，可能丢、乱序   | **可靠**（确认重传、排序、校验）   |
| 速度/开销 | 快、头 8 字节            | 慢一点、头 20+ 字节                |
| 传输形态  | 数据报（一条条独立）     | 字节流（连续无边界）               |
| 场景      | DNS 查询、视频直播、游戏 | 网页、文件、登录、一切要准的       |

选型一句话：**丢一帧画面无所谓但延迟致命 → UDP；一个字节都不能错 → TCP**。UDP 的"不可靠"常由应用层自建可靠机制（QUIC = UDP 上的现代 TCP+TLS）。

## 4.3 三次握手：建立连接（背到条件反射）

📌 **比喻**：对暗号确认双向畅通——A："听得到吗？"（①）B："听得到！你听我吗？"（②）A："听得到！"（③）——双方都确认了**我能发你能收、你能发我能收**。

```
客户端                          服务器
   │ ① SYN（seq=x）             │
   │ ─────────────────────────▶ │  收到 SYN：进入 SYN_RCVD
   │ ② SYN+ACK（seq=y, ack=x+1）│
   │ ◀───────────────────────── │
   │ ③ ACK（ack=y+1）            │
   │ ─────────────────────────▶ │  双方进入 ESTABLISHED
```

**为什么恰好三次、两次不行？** 两次无法确认"客户端能收"（B 的应答可能丢失/过期滞留——历史失效的连接请求会在网络里漂荡，两次握手会让服务器为幽灵请求白白开连接）。**四次冗余**（②③可合并为 SYN+ACK）。三次 = 确认双向信道 + 双方收发能力的最小交换。

## 4.4 四次挥手：断开连接

📌 **比喻**：挂电话四步——"我说完了"（①FIN）→"知道了"（②ACK）→（对方还有最后几句）"我也说完了"（③FIN）→"好的挂了"（④ACK）。

```
   │ ① FIN ───────────────────▶ │
   │ ◀────── ② ACK ─────────────│  服务器进入 CLOSE_WAIT（可能还有数据要发）
   │ ◀────── ③ FIN ─────────────│  数据发完才发 FIN
   │ ④ ACK ───────────────────▶ │
   │ [TIME_WAIT 等 2MSL]         │  客户端等 2 倍报文寿命后才真正关闭
```

**为什么四次**（比握手多一步）：收到 FIN 只代表"对方不发了"，**我可能还有数据没发完**——ACK 与 FIN 之间隔着收尾工作，不能合并。**TIME_WAIT 等 2MSL** 的原因：① 确保最后的 ACK 送达（丢了对方重发 FIN 我还能应答）；② 让旧连接的残余报文在网络中自然消亡（防串到新连接）。

**TCP 状态机高频状态**：SYN_SENT、SYN_RCVD、ESTABLISHED、CLOSE_WAIT（对端关了我没关——大量堆积=代码忘 close）、TIME_WAIT。

### TCP 报文头：每个字段都在讲机制

20 字节固定头，逐字段对应本章机制：

```
源端口(16) 目的端口(16)          ← 找进程（4.1）
序号 seq(32)                     ← 字节流编号（可靠传输的坐标）
确认号 ack(32)                   ← "期望收到的下一个字节号"（确认机制）
标志位(9)：SYN ACK FIN RST PSH URG ECE CWR  ← 握手/挥手/重传的信号灯
窗口(16)                         ← rwnd 接收窗口通告（流量控制）
校验和(16)                       ← 整段校验（防传坏）
```

**SEQ/ACK 口诀**：seq 是"我从第几个字节开始发"，ack 是"我已收到你第 ack−1 字节，请发第 ack 字节"。三次握手 `(x)(y,x+1)(y+1)` 的数字游戏全由这两个字段演出。**RST 位**突然复位连接（端口没监听/防火墙拒绝时常见）；**PSH** 提示"赶紧交给应用别攒着"。

## 4.5 可靠传输：确认、重传、滑动窗口

**可靠 = 不丢、不乱、不重、不丢节奏**。四大机制：

1. **序号与确认（ACK）**：每个字节编号；接收方 ACK"我已收到第 x 字节前的一切"；
2. **超时重传**：发出后启动定时器，超时未确认就重发（RTO 动态调整，指数退避）；
3. **快速重传**：收到 **3 个重复 ACK** 立即重传（不等超时——丢包信号比超时快）；
4. **滑动窗口**：**流水线式的发送**——不用发一个等一个，可同时发出"窗口内"多个段，ACK 右移窗口（对照流水线：并行度换吞吐）。

📌 **比喻**：窗口 = 你同时寄出的 N 个包裹；每收到一张"已签收 3 号"回执，窗口右滑一个新包裹上路——**管道充满，速率 = 窗口/RTT**。

## 4.6 流量控制与拥塞控制

**流量控制**（端到端，保护**接收方**）：接收方在 ACK 里通告**剩余缓冲窗口 rwnd**——发送方不能发出超过它的量（防"对方读不过来被淹"）。

**拥塞控制**（全局，保护**网络**）——四算法一套循环：

```
① 慢启动：cwnd 从 1 MSS 指数增长（每 RTT 翻倍）——试水温
② 拥塞避免：cwnd 到阈值后改线性加增（每 RTT +1）——稳步推进
③ 快重传：3 个重复 ACK → 立即重传丢失段
④ 快恢复：cwnd 减半、阈值减半，继续线性加增（遇超时则回到慢启动从头来）
```

📌 **比喻**：新手司机上高速——先慢开试探（慢启动），平稳后匀速渐进（拥塞避免），一堵车立刻减速一半（快重传+快恢复），彻底堵死则回起点重新试探。

# n05 应用层：HTTP、HTTPS、DNS

> 本章目标：离你最近的一层——浏览器、网站、域名的全部机制。HTTP 报文、状态码、HTTPS 加密原理、DNS 解析，是 Web 开发（PHP/Java/Python 卷）的协议底座。

---

## 5.1 HTTP：一问一答的协议

📌 **比喻**：点菜——顾客递菜单勾选（**请求**），服务员端菜回桌（**响应**）；每一单独立，服务员不记得你昨天点过什么（**无状态**——Session/Cookie 是补记忆的贴纸，PHP 卷第 8 章）。

📐 **HTTP 请求报文**：

```
GET /index.html HTTP/1.1        ← 请求行：方法 路径 版本
Host: www.example.com           ← 请求头（一组键值）
User-Agent: Mozilla/5.0
（空行）
[请求体：POST 时带数据]           ← 请求体
```

**方法语义**：GET（查）、POST（增/提交）、PUT（改）、DELETE（删）、HEAD（只要头）。**响应报文**：`HTTP/1.1 200 OK` + 响应头（Content-Type 等）+ 响应体（HTML/JSON）。

**HTTP 版本演进**：1.0（一请求一连接）→ 1.1（**长连接** keep-alive 复用 TCP、管线化）→ **2**（二进制分帧、多路复用：一个连接并发多个请求，告别队头堵塞）→ **3**（改用 QUIC/UDP，避免 TCP 层队头阻塞）。

**状态码五族**（背熟）：

| 族   | 含义     | 常见成员                                                 |
| ---- | -------- | -------------------------------------------------------- |
| 1xx  | 进行中   | 101 换协议                                               |
| 2xx  | 成功     | 200 OK、201 已创建、204 无内容                           |
| 3xx  | 重定向   | 301 永久移走、302 临时、304 缓存还新鲜                   |
| 4xx  | 客户端错 | 400 格式错、401 未认证、403 禁止、404 没找到、429 太频繁 |
| 5xx  | 服务器错 | 500 内部错误、502 网关坏、504 网关超时                   |

## 5.2 HTTPS：加密的 HTTP

📌 **比喻**：普通信件可被邮差拆阅（HTTP 明文）；HTTPS = **保险箱寄信**——先核对对方的"官方认证身份证"（**证书**），再用协商出的**临时对称钥匙**上锁通信。

📐 **HTTPS = HTTP over TLS**。握手简化流程（TLS 1.2 视角）：

```
① 客户端："你好，支持哪些算法？"（带随机数）
② 服务器：出示证书（含公钥，由 CA 签名背书）+ 随机数
③ 客户端验证证书（CA 公钥验签、域名、有效期）→
   生成预主密钥，用服务器公钥加密发出
④ 双方用三个随机数算出会话密钥 → 之后全部用对称加密通信
```

**两把钥匙的分工**：**非对称加密**（公钥加密、私钥解密）只用于握手阶段交换密钥（慢但安全）；**对称加密**（双方同钥，快）用于实际数据——各取所长的混合方案。**证书链**：根 CA → 中间 CA → 网站，浏览器内置根证书做信任锚——"为什么自签证书浏览器报警"的答案（无可信背书）。

三大安全属性：**加密**（窃听者只见乱码）、**完整性**（篡改会被 MAC 校验发现）、**身份认证**（证书防假站）。这也解释了第 10 章安全清单里"HTTPS 是 Cookie secure 属性的前提"。

## 5.3 DNS：互联网电话簿

📌 **比喻**：你记朋友名字（域名），打电话要查号码本（DNS）拿真实号码（IP）。

📐 **解析流程**（分级缓存接力）：

```
浏览器缓存 → 系统 hosts/缓存 → 本地 DNS 服务器（运营商）
  → 未命中则递归查询：根域名服务器（.）→ 顶级域（.com）→ 权威域名服务器（example.com）
  → 拿到 IP 一路缓存返回（TTL 控制缓存时长）
```

记录类型速记：**A**（域名→IPv4）、AAAA（→IPv6）、**CNAME**（别名→另一域名）、MX（邮件服务器）、NS（权威服务器）。DNS 基于 **UDP 53**（快；区域传送用 TCP）。

## 5.4 其他应用层协议速览

- **DHCP**：插网线自动分 IP（申请-提供-请求-确认四步）；
- **SMTP/POP3/IMAP**：发信/收信两种姿势；
- **FTP/SSH**：文件传输（21）/加密远程登录（22）；
- **CDN**：内容分发网络——把静态资源缓存到全球边缘节点（"就近取件"，DNS 智能调度实现）。

# n06 综合：一次 URL 请求的一生

> 本章目标：把五层模型、三大地址、TCP/UDP、HTTP/DNS 全部串成一条线——"浏览器输入网址回车后发生了什么"（面试史诗级经典题，也是本卷的毕业答辩题）。

---

## 6.1 全程拆解（十一步走完互联网）

```
① 输入 URL 回车
② DNS 解析（n05）：域名 → IP（逐级缓存：浏览器 → 系统 → 本地 DNS → 根/顶级/权威）
③ 应用层构造 HTTP 请求（n05）：GET / HTTP/1.1 + Host 头
④ 传输层 TCP（n04）：与服务器 443/80 端口三次握手；HTTPS 再加 TLS 握手换密钥
⑤ 网络层封装 IP 包（n03）：源 IP、目的 IP、TTL——查路由表确定下一跳（默认网关）
⑥ 链路层（n02）：ARP 拿网关 MAC → 封帧 → 物理层变比特发出（n01 封装洋葱成型）
⑦ 途中：每过一个路由器 TTL−1、MAC 换段、按路由表选下一跳（可能 NAT 改写）
⑧ 服务器侧逐层解封 → 交给 Web 服务进程（端口定位）→ 处理并返回 HTTP 响应
⑨ 原路返回：TCP 确认重传保障可靠（n04）、拥塞窗口控制速率
⑩ 浏览器收到响应：解析 HTML → 再发起 N 个请求（CSS/JS/图片——每张都是同样的循环）
⑪ 渲染显示页面；连接保持（keep-alive）复用或四次挥手关闭
```

**每一步都能归位到某一章**——这就是"体系建成"的自测标准：随机抽第 4 步、第 7 步都能展开讲 5 分钟。

## 6.2 网络故障排查思路（工程实用版）

按分层**自下而上**排查（每一层依赖下一层）：

| 症状                  | 先查                                     | 命令                                          |
| --------------------- | ---------------------------------------- | --------------------------------------------- |
| 完全不通              | 物理层：网线/Wi-Fi/网卡                  | `ipconfig`、指示灯                            |
| ping IP 通、域名不通  | DNS（n05）                               | `nslookup 域名`                               |
| ping 域名通、网页不通 | 应用层/防火墙/端口                       | `curl -v`、`telnet host 80`                   |
| 能连通但很慢          | 带宽/路由/丢包                           | `ping` 看 RTT 与丢包、`traceroute` 看断在哪跳 |
| 本机服务别人访问不到  | 防火墙、监听地址（0.0.0.0 vs 127.0.0.1） | `netstat -ano`                                |

（对照计网卷心法：**分层排查 = 把未知问题切成已知层次**——与 OS 卷排查、组成原理排障同一方法论。）

## 6.3 四门课最终串联（全系列收官图）

```
你在浏览器输入网址回车
 ├─ 组成原理：键盘中断 → CPU 流水线执行浏览器进程 → Cache/内存/总线的数据舞蹈
 ├─ 操作系统：进程调度浏览其 CPU 时间 → 系统调用发网络数据 → DMA+中断收包 → 页缓存
 ├─ 数据结构：路由表查表（前缀树/Trie）、TCP 窗口（滑动窗口）、浏览器 DOM 树、
 │            页面缓存（LRU）、DNS 负载均衡（哈希）
 └─ 计算机网络：DNS → TCP 握手 → HTTP → 五层封装解封 → 跨越互联网
       ▼
 网页渲染完成 —— 四门课各司其职，缺一不可
```

**四门基础课从来不是四门考试，而是同一个真实系统的四个切面**。C/Java/Python/PHP 四卷教你"写"，这四门课教你"懂"——写与懂合体，才是完整的计算机学习者。
