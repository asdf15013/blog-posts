## 0. 逆向是什么

**逆向工程（Reverse Engineering，RE）**：拿到别人**编译好的**程序，把它"倒推"回源码逻辑。正向是"写代码→编译→程序"，逆向就是"程序→读汇编/反编译→还原逻辑"。

CTF 逆向题的标准形态：

- 给你一个二进制（ELF / Windows EXE / APK / pyc / so……）
- 程序里藏着一段**校验逻辑**：你输入一个字符串，它判断对错（Wrong / Correct）
- flag 通常 = **正确的输入本身**，或**用程序里的算法解密出的字符串**

> **通俗理解**：Pwn 是"撬锁"——找锁的结构性缺陷撬开它拿东西；逆向是"拆锁画图纸"——把锁拆开一个零件一个零件看懂，配一把正确的钥匙。

### 0.1 逆向与 Pwn 的区别（一张表看懂）

|        | Pwn                                                      | Reverse                            |
| ------ | -------------------------------------------------------- | ---------------------------------- |
| 目标   | 漏洞利用，拿远程 shell / 读 flag                         | 理解算法，算出正确输入 / flag      |
| 环境   | 远程服务器（nc 连过去打）                                | 离线本地分析（程序发给你随便玩）   |
| 关心点 | 内存布局、溢出、执行流劫持                               | 算法逻辑、加密解密、反调试         |
| 产出   | exp 脚本                                                 | 解密脚本 / 正确输入 / patch 过程序 |
| 交集   | 汇编、ELF、调试器、IDA —— **两个方向一半的技能是共享的** |                                    |

### 0.2 逆向的两大解题思路

1. **算法还原（主流）**：读懂校验逻辑，用 Python 写"逆运算"脚本，直接算出答案
2. **patch 爆破（取巧）**：改程序字节码，把"判错"改成"判对"——但 flag 多数时候藏在输入里，patch 过了也拿不到 flag，只能证明逻辑看懂了

**判断用哪招**：flag 打印自输入 → 必须还原算法；只是"答对就给 flag"（出题人把 flag 用你的输入解密）→ 看情况；纯"过校验就弹 flag 文件" → 可爆破

## 1. C语言必备知识

逆向 90% 的题在"还原一段 C 代码的逻辑"，所以 C 的几个硬概念必须条件反射级熟悉。

### 1.1 变量在汇编里长什么样

```c
int main() {
    int a = 1;            // 局部变量
    static int b = 2;     // 静态 → .data
    int arr[4];           // 局部数组
}
```

| C 里写法            | 编译后的位置 | 汇编里长这样                           |
| ------------------- | ------------ | -------------------------------------- |
| 局部变量 `a`        | 栈上         | `mov dword [rbp-0x4], 1`               |
| 局部数组 `arr`      | 栈上连续一段 | `[rbp-0x20]` ~ `[rbp-0x10]`            |
| 静态/全局（有初值） | `.data` 段   | 固定地址 `mov ds:dword_404020, 2`      |
| 全局（无初值）      | `.bss` 段    | 固定地址，运行时清零                   |
| 字符串常量          | `.rodata` 段 | `lea rdi, aCorrectFlag   ; "Correct!"` |

**规律：`[rbp-XX]` 是局部变量，`dword_XXXXXX / byte_XXXXXX` 是全局变量，`aXxx`（IDA 命名）是 .rodata 字符串。**

### 1.2 数组与指针：逆向最常打交道

```c
int arr[5] = {10,20,30,40,50};
arr[i]      // 汇编：mov eax, [rbp + i*4 + arr偏移]  —— 基址 + 下标×元素大小
char *p = "abc";
p[i]        // movzx eax, byte [rdx + i]
```

识别口诀：**看到 `[reg + reg*4]` 就是 int 数组遍历，`[reg + reg*8]` 是 64 位数组或指针数组，`byte [reg + reg]` 是字符串逐字符处理**（逐字符处理 = 八成在做加密变换）。

### 1.3 字符串与字符运算

C 语言没有字符串类型，字符串 = **字符数组 + 结尾 `\0`**。逆向题最爱在字符上做文章：

```c
c - '0'            // 字符 '7' → 数字 7
c + 32             // 大写变小写
c ^ 0x20           // 大小写翻转（第三位取反）
c - 32             // 小写变大写
c & 0xDF           // 变大写（清掉 0x20 位）
'A' <= c && c <= 'Z'  // 是大写字母吗
```

逆向时看到 `>= 0x41 && <= 0x5A` 之类的比较，要马上反应过来这是在**检查字符范围**（flag 的字符集限制）。

### 1.4 结构体与内存对齐

```c
struct User { char name[8]; int age; long score; };
```

内存布局（64 位，8 字节对齐）：

```
偏移  0x00: name[8]      （8 字节，正好占满）
偏移  0x08: age          （int 4 字节 + 4 字节填充）
偏移  0x10: score        （long 8 字节）
总大小 0x18
```

逆向看到 `[reg + 0x10]`、`[reg + 0x8]` 这样**固定偏移访问一块内存**，就是在摸结构体成员。IDA 里按 `Y` 键给变量套上结构体类型，伪代码瞬间可读。

### 1.5 位运算（逆向的重中之重）

一半的逆向题核心就是位运算，必须像背九九乘法表一样熟：

| 运算      | 大白话                     | 常见用途                                      |
| --------- | -------------------------- | --------------------------------------------- |
| `&` 与    | 两个都是 1 才是 1          | 取某一位：`x & 1` 取最低位；清位：`x & ~0x10` |
| `\|` 或   | 有 1 就是 1                | 置位：`x \| 0x40`                             |
| `^` 异或  | **不同为 1，相同为 0**     | 加解密、翻转位                                |
| `~` 取反  | 0 变 1，1 变 0             | 配合 & 清位                                   |
| `<<` 左移 | 二进制整体往左挪，低位补 0 | `x << n` = ×2ⁿ                                |
| `>>` 右移 | 往右挪，高位补 0（无符号） | `x >> n` = ÷2ⁿ                                |

**异或的三条金律**（解密题的命根子）：

```
a ^ a = 0        （自己异或自己 = 0）
a ^ 0 = a        （异或 0 不变）
交换律/结合律    （顺序随便换）
```

推论——**"加密即解密"**：

```
密文 = 明文 ^ key
明文 = 密文 ^ key      ← 同一个式子，再来一遍就还原了
```

所以看到 `xor` 循环处理输入，先别慌，八成把密文再异或一遍就出 flag。

其他高频小套路：

```c
x & 1              // 判奇偶
(x >> i) & 1       // 取第 i 位
x ^= y; y ^= x; x ^= y;   // 不用临时变量交换两数
c ^ 0x20           // 大小写互换
x = -x             // 补码：按位取反加一 (~x + 1)
```

### 1.6 常见库函数的内联识别

开了优化后 `strcpy`/`memcpy` 会被编译器直接展开成循环，看不到 `call strcpy`。特征：

- **rep movsb / rep movsd**：memcpy 的 SSE/串指令版
- 简单字节循环复制：memcpy
- 判断 `\0` 的复制循环：strcpy
- `strlen`：循环找 `\0`，或 `repne scasb`

## 2. 汇编阅读

不用会写汇编，但要能"读"。逆向的读法跟 Pwn 不一样：**Pwn 看栈布局，逆向看控制流**——重点是认出 if、循环、switch 这些高级结构。

### 2.1 if / else 的识别

C 代码：

```c
if (a == 0x10)
    puts("Right");
else
    puts("Wrong");
```

汇编模式（**比较 + 条件跳转**）：

```asm
cmp  [rbp+var_8], 0x10
jnz  short loc_WRONG     ; 不等于 0x10 就跳去 Wrong
lea  rdi, aRight         ; "Right"
call puts
jmp  short loc_END
loc_WRONG:
lea  rdi, aWrong         ; "Wrong"
call puts
loc_END:
```

**读法**：`jz/jnz` 的目标地址决定走向——跳过去的那个分支是"条件不成立"的分支。`cmp X, Y` + `jz` 翻译成"X == Y 就……"。

### 2.2 循环的识别

```asm
mov  [rbp+var_i], 0          ; i = 0（循环变量初始化）
loc_LOOP:                    ; ← 回跳目标，循环体开始
mov  eax, [rbp+var_i]
cmp  eax, 0x20
jge  loc_END                 ; i >= 0x20 跳出 → 循环 32 次（0x20 次！）
...  循环体（数组处理、异或变换都在这）...
add  [rbp+var_i], 1          ; i++
jmp  loc_LOOP                ; ← 无条件往回跳 = 循环铁证
loc_END:
```

**识别三要素：初始化计数器、条件比较跳出、末尾回跳。** 循环次数（`cmp eax, 0x20` = 32 次 = flag 长度可能是 32）经常直接告诉你 flag 有多长。

### 2.3 switch 的识别

- **case 值连续**（如 0~3）→ 编译器生成**跳转表**：`jmp qword ptr [table + rax*8]`，一张表按索引直接跳
- **case 值稀疏** → 退化成 if-else 链

逆向题里 switch 常见于"菜单程序"和"状态机"。IDA 的流程图视图（空格切换）看跳转表一目了然。

### 2.4 函数调用

```asm
mov  rdi, r15               ; 参数1
mov  rsi, r14               ; 参数2
call sub_401360             ; 调用函数，返回值在 eax/rax
test eax, eax               ; 检查返回值
jz   loc_FAIL               ; 返回 0 = 失败
```

`sub_XXXXXX`（IDA 对无名函数的默认命名）就是"没认出来的函数"，通常正是**出题人自己写的校验函数**——双击进去就对了。

### 2.5 从一坨汇编里下手的方法论

面对几千行汇编别慌，按这个顺序切：

1. **先找 main**（IDA 自动识别；或从 `_start` 的第一条 call 跟）
2. **看字符串**：`Shift+F12` 列出所有字符串，找 "flag"/"Wrong"/"Correct" → 按 `X` 看谁引用它 → 直接空降到关键函数
3. **画调用图**：main 调了谁、谁又调了谁，IDA 显示为图，主干两三层就能看完
4. **只读循环和比较**：赋值搬运可以跳过，`cmp/jcc/xor/移位` 才是逻辑
5. 实在看不懂 → 换动态调试（第 6 章）

## 3. 可执行文件格式

### 3.1 快速判断：file 一把梭

```bash
$ file crackme
crackme: ELF 64-bit LSB executable, x86-64, statically linked, stripped
```

要看的三点：**架构（32/64、x86/ARM）、链接方式（静态带符号多/动态）、是否 stripped（剥符号）**。Windows 题则是 `PE32 executable (GUI) Intel 80386` 之类。

### 3.2 ELF 再深入（逆向视角）

Pwn 篇讲过 section 基础，逆向再补几个：

| section       | 逆向意义                                                     |
| ------------- | ------------------------------------------------------------ |
| `.rodata`     | 字符串常量集中营，**找提示语/密钥表的第一站**                |
| `.data`       | 有初值全局变量——**密钥、密码表常在这**                       |
| `.init_array` | main 之前执行的构造函数，**出题人爱在这藏初始化/反调试**     |
| `.symtab`     | 符号表：函数名、变量名。**没 stripped 时是巨大外挂**（直接看到 `check_flag` 这种函数名） |

### 3.3 PE 格式（Windows 逆向必背）

EXE 的结构层次：

```
DOS Header（"MZ" 魔数）→ 只为兼容，头部的 e_lfanew 指向 PE 头
PE Header（"PE\0\0" 魔数）
├─ File Header（机器类型、节数）
├─ Optional Header（**入口点 AddressOfEntryPoint**、ImageBase、子系统）
└─ 节表（Section Table）
节数据：.text（代码）/ .rdata（只读数据、导入表）/ .data / .rsrc（资源：图标、对话框）
```

逆向要点：

- **入口点**：程序从哪开始跑（壳会把入口改到自己那——见第 10 章）
- **导入表（IAT）**：程序用了哪些 Windows API——看到 `IsDebuggerPresent` 就是明示反调试；看到 `VirtualAlloc` 可能要解密/脱壳
- 加壳程序特征：**节名异常**（UPX0/UPX1、.vmp0）、**入口点指向最后一个节**、导入表只有寥寥几个函数（LoadLibrary/GetProcAddress）

### 3.4 stripped 之后怎么办

符号被剥（`stripped` / 函数全是 `sub_XXXX`）时靠三样东西找北：

1. **字符串**（提示语永远藏不住）
2. **系统调用/库函数**：IDA 的 FLIRT 签名库自动认出 `printf`、`malloc` 等标准库函数
3. **调用约定与代码模式**：谁被 main 直接 call、参数怎么传，推断功能

## 4. 编译优化的痕迹

### 4.1 编译四步（知识地图）

```
.c →(预处理)→ .i →(编译)→ .s 汇编 →(汇编)→ .o 目标文件 →(链接)→ 可执行文件
```

逆向拿到的是最后一步的产物，往回推。**优化等级（-O0 ~ -O3）决定了"还原难度"**：

| 等级         | 特征                               | 逆向感受               |
| ------------ | ---------------------------------- | ---------------------- |
| O0（无优化） | 变量全在栈上、步步贴 C 代码        | 新手友好，出题人仁慈   |
| O1/O2        | 变量进寄存器、小函数内联、循环展开 | 伪代码开始"不像人写的" |
| O3           | 激进内联、向量化                   | 寄存器满天飞，建议动调 |

### 4.2 常见优化模式（认出它，别慌）

编译器把你的乘除全改写成位运算和魔数，看到这些要知道**原本是什么**：

| 汇编模式                                 | 原本的 C 代码                                                |
| ---------------------------------------- | ------------------------------------------------------------ |
| `shl eax, 2`                             | `x * 4`                                                      |
| `lea eax, [rax + rax*4]`                 | `x * 5`                                                      |
| `add rax, rax`                           | `x * 2`                                                      |
| `and eax, 1`                             | `x % 2`                                                      |
| `mov edx, 0x66666667; imul ...; sar ...` | `x / 10`（**魔数除法**，÷10 的专属魔数 0x66666667，见到就当除法看） |
| `mov edx, 0xCCCCCCCD; ...`               | `x / 10`（无符号版）                                         |
| 直接消失的 if(1)                         | 常量折叠/死代码消除                                          |

### 4.3 内联（inline）

小函数被直接塞进调用处——所以"伪代码里找不到那个函数"很正常，它被摊平了。特征：同一段小逻辑在多处重复出现。

### 4.4 实战建议

- 拿到题先看是 O0 还是 O2：**变量名全是 `v1 v2 v3` 且贴栈 → O0 好读；全是寄存器 → 上 F5 伪代码 + 动调**
- 不要试图逐行还原优化后的汇编，**抓语义**：这个循环在干嘛、比较的对象是什么

## 5. 静态分析工具

> **通俗理解**：静态分析 = 看X光片（程序不动，你看它）；动态调试 = 开直播跟拍（程序跑起来，你贴身跟着）。

### 5.1 IDA Pro——行业硬通货

**为什么是它**：反编译器（F5）把汇编直接翻成 C 伪代码，准确率业界最高，且能 patch、能调试、插件生态大。

**标准工作流**：

```
打开文件 → 等分析完 → F5（反编译 main）→ 读伪代码 → 卡住就 Shift+F12 看字符串
→ X 交叉引用空降 → N 重命名变量让伪代码可读 → Y 改类型（套结构体）
```

**必背快捷键**：

| 键          | 功能                                 |
| ----------- | ------------------------------------ |
| `F5`        | 反编译成 C 伪代码（**灵魂功能**）    |
| `空格`      | 图形视图 / 文本视图切换              |
| `Shift+F12` | 列出所有字符串                       |
| `X`         | 交叉引用（谁用了这个字符串/函数）    |
| `N`         | 重命名（把 v1 改成 key，可读性暴涨） |
| `Y`         | 修改变量类型                         |
| `G`         | 跳到指定地址                         |
| `Esc`       | 返回上一个浏览位置                   |
| `;`         | 加注释                               |

### 5.2 Ghidra——免费开源之光

NSA 开源，功能对标 IDA（含反编译器），**没钱买 IDA 就用它**。界面类似：Symbol Tree 找函数、Listing 看汇编、 Decompiler 窗口看伪代码。还支持写 Java/Python 脚本批量处理（对付混淆题神器）。

### 5.3 命令行流：objdump / radare2

```bash
objdump -d -M intel crackme      # 反汇编全部（快速 grep 关键指令）
strings crackme | grep -i flag   # 不开 IDA 先捞字符串
r2 -A crackme; r2> afl           # radare2：分析+列函数（命令行版 IDA，大文件快）
```

### 5.4 字符串大法（新手第一课）

**字符串是程序的"口供"**：

1. `Shift+F12` 全部列出
2. 盯三类：**提示语**（Wrong/Correct/Password）、**密钥样**（一串怪字符）、**flag 格式片段**（ctfshow{、flag{）
3. 双击进入 → 按 `X` 看交叉引用 → 直接跳到用它的代码 —— **从"Correct"反查到的函数 90% 就是校验函数**

### 5.5 识别库函数：FLIRT

IDA 自带签名库，自动把标准库静态函数标注出来（`printf`、`strcpy`…）。剩下的 `sub_XXX` 基本就是出题人自己写的——**重点照顾对象**。

## 6. 动态调试

### 6.1 什么时候上动态

- 静态伪代码看不懂（优化猛、逻辑绕）
- **想看运行时的真实数据**：key 是什么、异或后的中间值长啥样
- 验证猜想："我怀疑这个函数在解密" → 断点看输入输出
- 对付只在运行时才解密的程序（SMC、壳）

### 6.2 Linux：gdb（pwn 篇老朋友）

```bash
gdb ./crackme
b main           # 断点
b *0x401234      # 地址断点
r                # 跑起来
info registers   # 看寄存器
x/s $rdi         # 把参数1当字符串看（函数断在入口时 = 看参数）
x/16xb $rsp      # 看栈上 16 字节
c                # 继续
```

逆向专用技巧：**断在函数入口看 rdi/rsi（参数），断在 ret 前看 rax（返回值）**——函数的输入输出一对比，算法作用就清楚了。

### 6.3 Windows：x64dbg / x32dbg

Windows 逆向标配调试器（中文界面），四大块：**反汇编 / 寄存器 / 内存 / 栈**。

| 操作             | 键   |
| ---------------- | ---- |
| 运行到断点       | `F9` |
| 单步（不进函数） | `F8` |
| 单步（步入函数） | `F7` |
| 下断点           | `F2` |
| 执行到光标处     | `F4` |

常用姿势：**右键 → 搜索 → 所有引用的字符串**（相当于 IDA 的字符串窗口），双击空降。`Ctrl+G` 跳地址。

### 6.4 断点的三种类型（选对工具事半功倍）

| 类型         | 原理                                    | 适用                                                         |
| ------------ | --------------------------------------- | ------------------------------------------------------------ |
| **软件断点** | 把目标字节改成 `0xCC`（int3）           | 日常默认。**缺点：改了代码 → 会被 CRC 自校验/0xCC 扫描发现** |
| **硬件断点** | 用 CPU 的调试寄存器 DR0-3，**不改内存** | 反调试场景；**最多 4 个**                                    |
| **内存断点** | 把一页内存设为不可访问，碰了就断        | **"谁读/写了这块数据？"**——盯密钥、盯 flag 缓冲区神器        |

> 记忆：软件断点像在门口贴条（会被发现），硬件断点像天上无人机盯着（无痕但名额少），内存断点像给房间装红外报警（谁碰谁知道）。

### 6.5 行为观察：strace / ltrace

不调试也行，先"偷看程序干了啥"：

```bash
strace ./crackme     # 它调了哪些系统调用（open 了什么文件？read 了多少字节？）
ltrace ./crackme     # 它调了哪些库函数（malloc 了多大？puts 了什么？）
```

程序半夜偷偷读 `/proc/self/status`（反调试）或 `open("/dev/urandom")`（随机化干扰），一眼看穿。

## 7. 常见加密算法识别

**逆向题 60% 的核心 = 认出题人用的加密算法**。好消息：大部分题不发明新算法，而是用现成的（或轻微魔改）。每个算法都有"指纹"。

### 7.1 特征速查总表（背下来就是外挂）

| 看到什么                                                     | 是什么                                 |
| ------------------------------------------------------------ | -------------------------------------- |
| 魔数 `0x9E3779B9`（delta）                                   | **TEA / XTEA / XXTEA** 家族            |
| 初始化 4 个值 `0x67452301 0xEFCDAB89 0x98BADCFE 0x10325476`  | **MD5**                                |
| 上面 4 个 + `0xC3D2E1F0`（第 5 个）                          | **SHA1**                               |
| `0x6A09E667` 打头的 8 个初始化常量                           | **SHA256**                             |
| 一张 256 字节的表，开头 `0x63 0x7C 0x77 0x7B...`（AES S盒）  | **AES**                                |
| 一张 256 项表，含 `0xEDB88320` 参与生成                      | **CRC32**                              |
| KSA：`for i in 0..255: S[i]=i` + 两两交换；PRGA：伪随机流异或 | **RC4**                                |
| 64 字符表 `ABC...abc...012...+/`，输出含 `=` 填充            | **Base64**（表换了就是变种）           |
| 输出只有 0-9a-f、长度 32/40/64                               | MD5 / SHA1 / SHA256 的**十六进制输出** |
| 纯 `xor` 循环 + 一个短 key 反复取模复用                      | **循环异或**（最常见）                 |
| 逐字符 `+ - ^ 乘` 加下标变换                                 | 自制变换题                             |
| 出现 RSA 特征：两个大素数、`pow(m, e, n)`、`e=65537`         | RSA（通常直接用 python 求逆）          |

### 7.2 循环异或（出现率最高）

伪代码长这样：

```c
for (i = 0; i < len; i++)
    out[i] = in[i] ^ key[i % keylen];
```

解密 = 同一个循环再来一遍（异或自反性）。key 要么明晃晃在 `.data` 里，要么本身就是已知字符串（"ctfshow" 之类）：

```python
enc = bytes.fromhex('1a2b3c...')
key = b'ctfshow'
print(bytes(c ^ key[i % len(key)] for i, c in enumerate(enc)))
```

### 7.3 Base64 与变种

原理：3 字节（24 位）切成 4 组、每组 6 位 → 查 64 字符表。

**变种题只干一件事：换表**。识别：伪代码里一张 64 字符表与标准表不同。解法——把表换回去再解：

```python
import base64
std = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/'
alt = 'ABC...题目给的表...'
print(base64.b64decode(s.translate(str.maketrans(alt, std))))
```

### 7.4 RC4（流密码，逆向常客）

特征：**KSA（打乱 S 盒）+ PRGA（生成密钥流逐字节异或）**，全程无魔数但有结构：

```python
def rc4(key: bytes, data: bytes) -> bytes:
    S = list(range(256)); j = 0
    for i in range(256):                      # KSA
        j = (j + S[i] + key[i % len(key)]) % 256
        S[i], S[j] = S[j], S[i]
    i = j = 0; out = bytearray()
    for b in data:                            # PRGA
        i = (i + 1) % 256; j = (j + S[i]) % 256
        S[i], S[j] = S[j], S[i]
        out.append(b ^ S[(S[i] + S[j]) % 256])
    return bytes(out)                          # 加解密同一个函数
```

### 7.5 TEA 家族

特征：`delta=0x9E3779B9`，`sum` 累加 32 轮，两 个 32 位 v0/v1 互相异或移位：

```python
def tea_decrypt(v0, v1, k):           # 32 轮，解密=加密的逆序
    delta, s = 0x9E3779B9, 0xC6EF3720  # 0xC6EF3720 = delta*32 mod 2^32
    for _ in range(32):
        v1 = (v1 - (((v0 << 4) + k[2]) ^ (v0 + s) ^ ((v0 >> 5) + k[3]))) & 0xFFFFFFFF
        v0 = (v0 - (((v1 << 4) + k[0]) ^ (v1 + s) ^ ((v1 >> 5) + k[1]))) & 0xFFFFFFFF
        s = (s - delta) & 0xFFFFFFFF
    return v0, v1
```

魔改点通常在：轮数改了、delta 换了、密钥顺序换了——对着伪代码逐项核对。

### 7.6 遇到"自制魔改算法"怎么办

1. **别急着复刻全部**——先确定输入输出的"变换方向"（加密 or 解密）
2. 写 Python 时**一步一步对拍**：在程序里下断点拿中间值，和脚本同步骤的结果比对，**第一个不一致的步骤就是抄错的地方**
3. 变换不可逆时（如 `x = x * x & 0xff` 丢信息）→ 换思路：爆破 / z3 / 直接动调改跳转

## 8. z3与符号执行

### 8.1 什么时候需要它

题目对 flag 的每一位都有一堆条件（`s[0]*2+1 == 33 && s[0]^s[1] == 88 && ...`），人工解方程会爆炸。**z3 是"约束求解器"——你把所有条件告诉它，它把满足条件的值算出来。**

> 通俗理解：普通脚本是"给输入算输出"，z3 是"给输出反推输入"——把出题人的方程组丢回去让他自己解。

### 8.2 z3 模板（背下来）

```python
from z3 import *

s = Solver()
flag = [BitVec(f'c{i}', 8) for i in range(32)]     # 32 个 8 位未知量

for c in flag:                                      # 通用约束：可见字符
    s.add(c >= 32, c <= 126)

# 把伪代码里的每个条件原样翻译进来（举例）
s.add(flag[0] + flag[1] == 0xD3)
s.add(flag[2] ^ 0x55 == ord('k'))
s.add(flag[3] * 2 == flag[4] + 7)
# ... 题目有多少条件加多少

if s.check() == sat:
    m = s.model()
    print(''.join(chr(m[c].as_long()) for c in flag))
else:
    print('无解，条件抄错了？')
```

要点：**把 IDA 伪代码的条件逐条"直译"成 `s.add(...)`**，不要自己化简——z3 就是为暴力方程组而生的。

### 8.3 angr：让程序自己找输入

angr 是符号执行引擎——**让它"带着未知数"跑一遍程序，自动找出到达 Correct 分支的输入**：

```python
import angr

proj = angr.Project('./crackme', auto_load_libs=False)
sm = proj.factory.simulation_manager()
sm.explore(find=0x4017B0, avoid=0x4017D0)   # find=Correct分支地址, avoid=Wrong分支
print(sm.found[0].posix.dumps(0))            # 打印满足条件的 stdin 输入
```

适用：**输入在前面、判断在后面、路径爆炸不严重**的题。路径太复杂（循环多）时 angr 会跑到天荒地老——退回 z3。

### 8.4 选型口诀

- 条件是**位级运算方程** → z3
- 条件是**长路径判断**（走迷宫、多分支到达） → angr / 手动分析
- 数据变换**有信息丢失**（不可逆） → 只能爆破或动调绕过

## 9. 反调试与混淆

出题人不想让你舒舒服服调试，会下绊子。**认识套路 → 一巴掌拍掉**。

### 9.1 常见反调试手段

| 手段                                   | 平台    | 原理                                         | 破法                                         |
| -------------------------------------- | ------- | -------------------------------------------- | -------------------------------------------- |
| `ptrace(PTRACE_TRACEME)`               | Linux   | 自己 attach 自己占坑，调试器再 attach 就失败 | patch 掉那个 call / 让它返回 0               |
| 读 `/proc/self/status` 查 `TracerPid`  | Linux   | 有调试器则非 0                               | hook 文件读取 / patch 判断                   |
| `IsDebuggerPresent`                    | Windows | 查 PEB 的 BeingDebugged 标志                 | 断在该 API，改返回值为 0；或改 PEB           |
| `CheckRemoteDebuggerPresent`           | Windows | 远程调试检测                                 | 同上                                         |
| **时间差检测**（rdtsc / GetTickCount） | 双平台  | 两条指令间耗时异常 → 断点让单步变慢          | 避开断点用硬件断点；或 patch 时间比较        |
| **CRC 自校验**                         | 双平台  | 对代码段算哈希，被下 0xCC 断点后哈希变了     | **用硬件断点**（不改代码）；或同步改回校验值 |
| 扫描 `0xCC`                            | 双平台  | 遍历代码段找软件断点                         | 硬件断点                                     |
| 检测 VMware/沙箱（CPUID、注册表）      | Windows | 反虚拟机分析                                 | patch 或改环境特征                           |

**通用心法：反调试代码本身也是代码——找到判断分支，patch 成"无调试"的走向即可。字符串里看到 `debugger`/`tracer` 或导入表里看到 `IsDebuggerPresent`，先去解决它。**

### 9.2 花指令

在真实指令间插垃圾字节/永假跳转，让反编译器对不齐字节流，F5 直接失败：

```asm
jmp short loc_real
db 0xE8            ; 垃圾字节（反编译器把它当 call 的开头，对不齐就崩）
loc_real:
...
```

**去花**：把 `jmp` 目标之间填充的垃圾字节改成 `nop`（0x90），或直接 patch 掉 jmp 结构。IDA 里逐个 patch（Edit → Patch program → Change byte），改完 F5 就活了。

### 9.3 OLLVM 混淆三大板斧

| 混淆                     | 特征                                                         | 应对                                                |
| ------------------------ | ------------------------------------------------------------ | --------------------------------------------------- |
| **控制流平坦化**（-fla） | 整个函数变成一个巨型 `while(1){switch(dispatcher){...}}` 转盘，所有基本块被打散重编号 | deflat 脚本（angr 系）；或动调跟主流程，无视支路    |
| **虚假控制流**（-bcf）   | 到处插入永假的 `if(opaque)` 假分支                           | 识别 opaque predicate（永远为假），IDA 插件自动剔除 |
| **指令替换**（-sub）     | `a+b` 换成 `(a^b)+2*(a&b)` 之类等价怪写                      | 硬读伪代码，或写脚本模式替换                        |

> 通俗理解：平坦化 = 把串好的项链倒进抽奖转盘，每颗珠子（代码块）靠转盘指针（dispatcher 变量）决定下一个是谁。**盯住 dispatcher 变量的取值顺序，就能把项链重新串起来。**

### 9.4 VM 保护（终极形态）

程序里出现一个**大 switch + 虚拟寄存器数组 + 自己的字节码**——出题人写了个"解释器"，把关键逻辑编译成了自定义字节码。以及商业壳 VMP / Themida 的虚拟化。

应对：要么硬啃解释器指令集（工作量大但一劳永逸），要么动调在解释器"取指令"处 trace 全部执行序列再还原。新手题一般不会上真 VM，**见到"巨型 switch + 数组当寄存器"先冷静识别，再决定投入**。

## 10. 壳与脱壳

### 10.1 壳是什么

**壳 = 套在程序外面的"压缩/加密包装"**。原始 EXE 被打包成数据，运行时先跑壳代码：解密原程序到内存 → 修复导入表 → 跳到原入口执行。

> 通俗理解：寄快递时把真东西（原始程序）装进保密箱（壳），到货后（运行时）先开箱再使用。脱壳 = 等它开完箱，把拿出来那一刻的内存拍下来还原成文件。

### 10.2 查壳

用 **Detect It Easy（DIE）** 或 PEiD 拖进去：显示 `UPX 3.x` / `VMProtect` / `Themida` / `ASPack` …

也可以肉眼看 PE 特征：**节名是 UPX0/UPX1/.vmp、入口点在最后一个节、导入表只有 LoadLibrary/GetProcAddress 几个函数** —— 九成有壳。

### 10.3 UPX（新手必会）

最经典的压缩壳，官方自带一键脱：

```bash
upx -d crackme.exe      # 脱壳成功 → 原样 EXE
```

不奏效（改了魔数不能脱）时手动脱：x64dbg 运行 → **单步到大跳转（jmp/ret 跳到老入口 OEP）** → 用 Scylla/dump 插件转存 + 修复导入表。

> OEP = Original Entry Point（原入口点）。压缩壳解压完必然有一个 `jmp OEP` 大跳转——**跨好几个节、跳到看起来像正常函数开头的地方**，就是它。（"ESP 定律"：壳代码遵守栈平衡，在 pushad/popad 后下硬件断点可精确抓 OEP。）

### 10.4 VMP / Themida

商业保护壳 + 虚拟化，**直接静态分析基本无望**。比赛遇到：要么题目只保护了关键函数（找未保护部分绕），要么走 trace + 动态数据侧攻击。新手阶段建议识别后跳过。

### 10.5 Android 加固

APK 也常被加固（梆梆、360、腾讯乐固）：`classes.dex` 变成一个壳 loader，真 dex 运行时释放。工具：FRIDA-DEXDump / BlackDex 运行时把真 dex 拖出来。

## 11. 非C目标的逆向

CTF 逆向不只有 C，这些"方言区"各有专属工具，**难度骤降——认出类型就赢了一半**。

### 11.1 Python（.pyc / PyInstaller）

特征：`file` 显示 `python 3.x byte-compiled`；PyInstaller 打包的单文件 EXE 里能看到 `MEI` 字样。

```bash
# PyInstaller 先解包拿出 pyc
python pyinstxtractor.py crackme.exe
# 反编译 pyc → py 源码（选一）
pycdc main.pyc             # 或
uncompyle6 main.pyc        # py3.8 以下
# 注意：pyc 头部 magic 要与 python 小版本匹配，报错先修头
```

**反编译成功 = 直接看到源码，题白给**。出题人会用字节码混淆/魔改 opcode 对抗——那就回 IDA 硬啃或手修字节码。

### 11.2 C# / .NET

特征：`file` 显示 `.NET assembly`，或 DIE 显示 `MS .NET`。

**dnSpy 拖进去直接看 C# 源码，还能改逻辑重新保存**——.NET 逆向全家桶就这一个工具。混淆后类名变 `AAAA` 系列的，用 de4dot 先洗一遍。

### 11.3 Java / APK

```bash
jadx-gui app.apk        # 一键反编译 apk → java 源码（看逻辑）
apktool d app.apk       # 拆资源/清单（smali 层，改逻辑用）
```

native 层（libxxx.so）回到 IDA 分析；运行时 hook 用 **Frida**（手机/模拟器 + `frida -U -l hook.js`）。

### 11.4 易语言

国产中文编程，常见于老牌国产 crackme。静态特征：节表/引用 `krnln.fnr`、`krnln.fne`。逆向时 IDA 配合"易语言函数识别脚本"能把 `sub_XXXX` 还原成中文函数名。**它底层还是 Windows API，按普通 PE 分析即可。**

### 11.5 Go / Rust

现代题越来越多。特征与要点：

- **Go**：符号一般不剥（函数名一大串 `main_main`），先看 `main.main`；字符串没有 `\0` 结尾，是"指针+长度"结构，IDA 里会显示成连体怪串
- **Rust**：panic 信息字符串丰富（`rust_begin_unwind`），顺着错误信息定位逻辑；符号 mangle 过但 `rustfilt` 可还原

## 12. patch爆破技术

> patch = 改程序机器码，让它按我们的意思走。**"打补丁过校验"**，也叫爆破。

### 12.1 先判断能不能爆破

| 场景                             | 能否爆破                             |
| -------------------------------- | ------------------------------------ |
| 输入正确 → 打印 `flag{你的输入}` | ❌ 必须还原算法（flag 依赖输入内容）  |
| 输入正确 → 程序自己解密打印 flag | ✅ 把"对错判断"patch 成恒对，随便输入 |
| 输入正确 → 才运行解密函数        | ✅ 爆破或动调直接跳进解密函数         |

### 12.2 经典 patch 点

**情况一：条件跳转改无条件**

```asm
test eax, eax
jz   loc_WRONG        ; 75 XX  → 改成 EB XX（jmp loc_WRONG 反向）或把 jz 改 jnz
```

常用字节替换表（记 3 个就够应付大多数题）：

| 原       | 字节                          | 改成     | 字节                | 效果                 |
| -------- | ----------------------------- | -------- | ------------------- | -------------------- |
| `jz`     | `74 XX`                       | `jnz`    | `75 XX`             | 条件取反             |
| `jnz`    | `75 XX`                       | `jz`     | `74 XX`             | 条件取反             |
| `jz/jnz` | `7x XX`                       | `jmp`    | `EB XX`             | 无条件跳（恒走一边） |
| `jz`     | `0F 84 xx xx xx xx`（长跳转） | `nop` ×6 | `90 90 90 90 90 90` | 直接不跳             |

**情况二：改比较值**——`cmp eax, 0x1337` 把 0x1337 改成你随便输入的数的值。

**情况三：交换真假分支**——把调用 `sub_打印Wrong` 和 `sub_打印Correct` 的两个 call 地址对调。

### 12.3 IDA patch 流程

```
定位指令 → Edit → Patch program → Change byte（或 Assemble 输入新汇编）
→ 全部改完 → Edit → Patch program → Apply patches to input file
→ 另存新文件 → 运行验证
```

### 12.4 x64dbg patch 流程

双击指令 → 输入新汇编（如 `jmp 0x4017B0`）→ 空白处右键 → **Copy to executable → All modifications** → 保存新 EXE。

### 12.5 Linux ELF 的 patch

IDA 同样支持（Apply patches）；或命令行流派：

```bash
# 把文件偏移 0x1234 处的 1 字节改成 0xEB（python 精准改字节）
python -c "
data = bytearray(open('crackme','rb').read())
data[0x1234] = 0xEB
open('crackme_patched','wb').write(data)
"
chmod +x crackme_patched && ./crackme_patched
```

> 提醒：**文件偏移 ≠ 虚拟地址**。IDA 里看到的是 VA，patch 文件时要 `VA - 段基址 + 段文件偏移` 换算（IDA 的 Apply patches 会自动做，自己 dd 时要手算）。

## 13. 常见题型套路

| 题型              | 识别特征                          | 解法思路                                           |
| ----------------- | --------------------------------- | -------------------------------------------------- |
| **逐字符变换**    | 单层 for + `in[i] ^/+/-/* c`      | 逆运算脚本（异或/加减可逆；乘要模逆）              |
| **现成加密**      | 魔数/表特征（第 7 章）            | 认出 → 标准库解密（pycryptodome）                  |
| **循环异或**      | xor + key[i % len]                | key 同 xor 一遍                                    |
| **迷宫**          | `.data` 里一张字符地图 + 方向输入 | 提取地图 → BFS/DFS 求路径 → 路径字符即 flag 或输入 |
| **约束求解**      | 每位输入一堆方程                  | z3 直译条件（第 8 章）                             |
| **反调试**        | 一调就退/崩                       | 第 9 章逐项排雷                                    |
| **花指令/混淆**   | F5 失败、函数巨乱                 | 去花；OLLVM 用 deflat / 动调主流程                 |
| **壳**            | DIE 一查便知                      | 第 10 章脱壳                                       |
| **自修改（SMC）** | 静态看代码与运行行为不符          | 动调，断在改写代码的时刻，dump 解密后的段          |
| **多阶段**        | 解开一层又一层                    | 耐心 + 脚本化；每层独立验证                        |
| **打表题**        | 一个大数组 + `flag = table[x]`    | 直接按索引取表拼 flag                              |
| **MD5 碰撞型**    | 要求 md5(输入) == 给定值          | 查彩虹库/搜索引擎；不可逆时看是否只校验部分        |

**迷宫题速解模板**（高频）：

```python
from collections import deque
maze = '''########
#S..#..#
#.#.##.#
#.#..E.#'''          # 从程序 .data 抄出来的地图
g = [list(r) for r in maze.splitlines()]
q = deque([((1,1), '')])
seen = {(1,1)}
while q:
    (x,y), path = q.popleft()
    if g[y][x] == 'E': print(path); break      # path 即方向序列
    for dx,dy,d in ((0,1,'s'),(0,-1,'w'),(1,0,'d'),(-1,0,'a')):
        nx,ny = x+dx, y+dy
        if g[ny][nx] != '#' and (nx,ny) not in seen:
            seen.add((nx,ny)); q.append(((nx,ny), path+d))
```

## 14. 完整解题流程

以一道典型 crackme 为例，把全流程串起来：

```
1. 摸底
   file crackme → ELF 64-bit, dynamically linked, not stripped
   ./crackme 跑一遍 → 提示 Input: → 随便输 → Wrong!

2. 查壳
   DIE / 看 PE 节名 → 无壳（有壳先去第 10 章）

3. 静态分析
   IDA 打开 → F5 main
   → 发现 main 调 sub_1234(input)，返回值判断打印 Right/Wrong
   → 进 sub_1234：32 轮循环、delta 0x9E3779B9 → TEA!

4. 提取素材
   .data 里找到 16 字节 key、密文 32 字节

5. 解密
   python 写 tea_decrypt（第 7.5 节模板）→ 跑出明文

6. 验证
   ./crackme 输入解出的明文 → Correct! → 提交 flag

   （若 flag 就是输入本身 → 直接交；若程序还要再算一层 → 继续跟）
```

**卡住时的检查清单**：

- F5 失败/伪代码稀碎 → 花指令？先去花（9.2）
- 逻辑看着对但解不出 → 中间值对拍（7.6），第一步不一致处就是抄错处
- 本地跑不起来 → 缺 libc？patchelf 换（pwn 篇 19.2）；要 argv/输入文件？看 strace
- 一调试就崩 → 反调试（第 9 章），换硬件断点
- 解出来是乱码 → 字节序（TEA 按 32 位小端解）、密钥顺序、轮数核对
- 实在无解 → z3 直译条件；或动调直接跳进"成功分支"看它打印什么

### 16.4 给新手的几句实在话

1. **先跑一遍程序再开 IDA**——知道它问什么、答什么，分析才有方向
2. **字符串大法永远是第一步**：提示语 → 交叉引用 → 空降核心函数，三步省一小时

5. 每题记三行笔记：**什么特征 → 什么算法/坑 → 什么解法**，比抄十篇 wp 有用
6. 和 pwn 互补着学：逆向练"读"，pwn 练"打"，汇编/IDA/调试器两边通用——**一个工具箱，两门手艺**
