# c01 计算机系统总览

> 本章目标：建立整机的骨架图——冯·诺依曼结构、五大部件、软硬件层次。后续章节就是把这张图逐块放大。

---

## 1.1 冯·诺依曼结构：一台"听话"的机器

📌 **比喻**：一位**严格按照乐谱演奏的乐手**——乐谱（程序）和乐谱上要唱的歌词（数据）都放在同一个曲谱架（存储器）上；乐手按节拍（时钟）一个音符一个音符地取谱、演奏；指挥（控制器）负责翻页与协调。

📐 **定义**：**冯·诺依曼体系结构（1945）**的核心思想：

1. **存储程序**：程序（指令）与数据**同等地存放在存储器中**，机器自动逐条取出执行——这是计算机能"自动工作"的根本（此前的机器靠插线/纸带硬编码）；
2. **指令按地址顺序执行**，用程序计数器（PC）记录下一条；
3. **五大部件**：**运算器**（ALU，算账的）、**控制器**（CU，指挥的）、**存储器**（存谱+词）、**输入设备**（抄谱进来）、**输出设备**（表演出去）。

现代演进（要认识的两个变体）：**哈佛结构**——指令与数据分开存储/总线（嵌入式、L1 Cache 分 I-Cache/D-Cache，避免取指取数抢路）；**改进的冯结构**——以存储器为中心、并行总线等。

## 1.2 五大部件与数据流

```
        ┌─────────────── 控制器 CU ───────────────┐
        │  （发号施令：取指、译码、协调）           │
        ▼                 ▼                      ▼
   输入设备 ──▶ 存储器（内存）◀──▶ 运算器 ALU
   (键盘)        （指令+数据）       （加减乘逻辑）
                     │
                     ▼
                 输出设备（屏幕）
```

数据流实例：`c = a + b` —— 输入设备把 a、b 存进存储器 → 控制器取"加法指令" → 运算器从存储器取 a、b 相加 → 结果写回存储器 → 输出设备取走展示。**一切指令都是"取数-运算-存数"的变奏**。

## 1.3 软硬件层次：洋葱模型

📌 **比喻**：洋葱从外到内一层层剥——最外层是使用者能摸到的（浏览器），最里层是电子流动（晶体管）。

| 层次           | 内容                      | 谁来"翻译"                  |
| -------------- | ------------------------- | --------------------------- |
| 高级语言层     | Python/C/Java 源码        | 编译器/解释器（C 卷/javac） |
| 汇编层         | mov/add 助记符            | 汇编器                      |
| **机器语言层** | 0/1 指令（本卷主角）      | CPU 直接执行                |
| 操作系统层     | 进程/内存/文件管理        | OS（OS 卷）                 |
| 微程序层       | 一条机器指令 = 一串微指令 | 控制器                      |
| 硬件逻辑层     | 门电路、触发器            | 物理电路                    |

**关键认知**：每层只跟相邻层打交道（你在 Python 里调一个函数，硬件层面是成千上万条指令的脉冲）——**分层让复杂性可控**，这与网络的分层（计网卷）是同一思想。

## 1.4 性能度量

- **主频（时钟频率）**：CPU 每秒的"节拍数"（3GHz = 每秒 30 亿拍），每个动作按拍计价；
- **CPI**：每条指令平均时钟周期数；
- **性能公式**：**时间 = 指令数 × CPI × 时钟周期**——三大优化杠杆：少跑指令（好算法/编译器）、降 CPI（流水线 c04）、提主频（工艺）；
- **摩尔定律**（经验律）：晶体管数约每 18~24 个月翻倍——近十年放缓，性能转向多核与专用芯片（GPU/NPU）。

## 易错点清单

1. 冯·诺依曼结构"以运算器为中心"是原始版——现代以**存储器为中心**（数据搬运是瓶颈）；
2. 主频高 = 一定快？（忽略指令数与 CPI——架构不同不能只比频率）；
3. 指令和数据存一起分不清怎么办？——靠**取指阶段/取数阶段**与 PC 指向区分（时序区分）。

3. 性能公式三要素？（指令数 × CPI × 时钟周期）

# c02 数据的表示与运算

> 本章目标：计算机里"数"长什么样——进制、补码（有符号数的标准答案）、浮点数 IEEE 754。这一章的每个结论都在你写代码时默默生效（int 溢出、0.1+0.2≠0.3 的根源）。

---

## 2.1 进制：同一数量的不同写法

📌 **比喻**：同一瓶水，标"500 毫升""0.5 升""2 杯"——数量不变，记法不同。计算机只有 0/1（二进制），人读着费劲，于是用**十六进制**压缩显示（每 4 位二进制 = 1 位十六进制：`1111` → `F`）。

转换三招：

- 二→十六：**从右每 4 位一组**（`1010 1100` → `0xAC`）；
- 十→二：除 2 取余倒读；小数部分乘 2 取整正读；
- 十六→十：按权展开（`0xAC` = 10×16 + 12 = 172）。

**注意**：十进制小数 0.1 转二进制是**无限循环**（0.000110011…）——浮点误差的种子在此埋下（2.4 节回收）。

## 2.2 原码、反码、补码：负数怎么存

📌 **比喻**：**时钟拨法**。现在是 10 点，想"减 2 小时"= 把指针**往回拨 2 格**，也可以**往前拨 10 格**（10+10=20→20−12=8，模 12 归一圈）——在"模"的世界里，**减一个数 = 加它的补数**。补码就是这套时钟算术。

📐 **定义**（8 位为例）：

- **原码**：符号位（0 正 1 负）+ 绝对值——直观但加减要分符号讨论，且 0 有两种表示（+0/−0）；
- **反码**：负数 = 原码按位取反（过渡用）；
- **补码**：负数 = 反码 + 1。**现代机器统一用补码存有符号数**。

补码三大红利：

1. **加减法统一**：减法直接当加法算（`5 − 3 = 5 + [−3 补码]`），ALU 不需要减法器；
2. **0 唯一**：00000000 只代表 0；
3. **表示范围不对称**：8 位补码范围 **−128 ~ +127**（−128 是 10000000，没有对应正数——256 个编码，0 占一个，正数只到 127，多出的一格给了 −128）。

取补码速算：**从右往左第一个 1 保留，其左边全部取反**。符号扩展：8 位 → 16 位，正数补 0、负数**补符号位**（11111111 → 1111111111111111 仍是 −1）。

**溢出判断**：两正得负、两负得正 = 溢出；或看**最高位进位与次高位进位是否相异**。（对照语言教程的 int 溢出实验：127+1 = −128 正是补码轮回。）

## 2.3 位运算速查

| 运算         | 符号                    | 用途示例                                                     |
| ------------ | ----------------------- | ------------------------------------------------------------ |
| 与 AND `&`   | 都 1 才 1               | 取位段、清零（`n & 0xFF` 取低 8 位）                         |
| 或 OR `\|`   | 有 1 则 1               | 置位（`n \| 0x80` 最高位置 1）                               |
| 异或 XOR `^` | 不同为 1                | 翻转位、**无临时变量交换**（a^=b;b^=a;a^=b）、找唯一出现奇数次的数 |
| 取反 NOT `~` | 0↔1                     | `~x = −x−1`（补码性质）                                      |
| 左移 `<<`    | 乘 2ⁿ（不溢出时）       | 快速乘法、拼位段                                             |
| 右移 `>>`    | 算术右移补符号位（÷2ⁿ） | 快速除法（负数向 −∞ 取整）                                   |

### 补码加减与溢出判断（运算器视角）

补码的世界里**加法器一个部件包打天下**（减法 = 加负数补码）。规则与判溢：

```text
  [x]补 + [y]补 = [x+y]补        （直接相加，超出位数的进位丢弃——"模"运算）

  例：8 位下  5 + (-3)：
      00000101
    + 11111101      ← -3 的补码
    = 1 00000010    → 丢弃第 9 位进位 → 00000010 = 2 ✓（模 256 归一圈）

溢出判断两法：
  ① 双符号位法：两符号位不同（01 或 10）→ 溢出
  ② 单符号位法：同号相加结果符号相异 → 溢出
```

**定点 vs 浮点**的取舍：定点（纯整数/纯小数）快而精确但范围窄；浮点范围天文但每步有舍入误差——**科学计算选浮点、账本选定点（分为单位整数）**的根源。原码一位乘、除法的"移位+加减"硬件流程属考试推导题，思想是"手工竖式计算的电路化"。

## 2.4 浮点数 IEEE 754：科学计数法的二进制版

📌 **比喻**：把数字写成**科学计数法**存三样东西：正负号、指数（定小数点位置）、有效数字（精度）。`−6.02×10²³` 存成：负号、23、602——位置与精度分开管。

📐 **定义**：**IEEE 754** 浮点 = **符号位 S + 指数 E（带偏移的阶码）+ 尾数 M**：

- **float（32 位）**：1 + **8** + 23 → 约 **7 位**十进制有效数字；
- **double（64 位）**：1 + **11** + 52 → 约 **15~16 位**；
- 尾数隐藏首位 1（规格化后必为 1.xxxx，白赚一位精度）；指数用**偏移码**（float 偏移 127）存（可表示负指数且便于比较）。

两大必然现象：

1. **0.1 存不精确**（二进制无限循环截断）→ `0.1+0.2 != 0.3`（多语言教程同款实验）；
2. **精度随大小退化**：大数加小数，小数被"吸掉"（10¹⁶ + 1 == 10¹⁶）。

特殊值：`±Infinity`（指数全 1 尾数 0，溢出/除零）、`NaN`（指数全 1 尾数非 0，0/0 等，自身不相等）、`±0`。**算钱用整型分/Decimal** 的根源在此（对照语言教程浮点章）。

## 易错点清单

1. 补码范围不对称（−128 无正对）——`abs(-128)` 是坑；
2. 左移负数/右移有符号数的行为差异（算术 vs 逻辑右移）；
3. 浮点数用 `==` 比较、累加大浮点数组——精度铁律（比较用差值容差）；
4. 忘记"尾数隐藏首位 1"导致手算 IEEE 754 全错。

# c03 存储系统：Cache 与局部性

> 本章目标：解决"CPU 快如闪电、内存慢如牛车"的矛盾——存储金字塔与 Cache。本章与 OS 卷虚拟内存互为镜像（Cache 对 CPU、分页对进程，同一思想两级应用）。

---

## 3.1 存储金字塔：快与大的不可兼得

📌 **比喻**：图书馆读书。**书桌**（寄存器，随手可取但只有几格）、**书架**（Cache，走到即取、容量小）、**阅览室**（内存，走几步、中等容量）、**库房**（磁盘，巨大但要登记借阅）。

📐 **定义**：存储器按速度/容量/价格分层：

```
        寄存器    ~0.3ns    KB 级     ← CPU 内部
      L1 Cache    ~1ns      数十 KB/核
      L2 Cache    ~4ns      数百 KB/核
      L3 Cache    ~15ns     数十 MB（共享）
      内存 DRAM   ~100ns    GB 级
      固态盘 SSD  ~100μs    TB 级
      机械盘 HDD  ~10ms     TB 级
```

**相邻层速度差百倍**——CPU 等一次内存 ≈ 它完成几百条指令的时间。**金字塔成立的根基是局部性原理**（OS 卷 o04.5）：时间局部性（刚用过的还会用）+ 空间局部性（用过的旁边会用到）——有了它，小 Cache 才能以"以小博大"的方式服务大程序。

## 3.2 Cache 工作原理：把常用搬到书架

📐 **工作流程**：CPU 要地址 A 的数据 → **先查 Cache** → 命中（hit）直接拿（快）；未命中（miss）→ 从内存取**整块（block，典型 64 字节）**搬入 Cache 再交给 CPU。**关键设计：搬的是一整块而非一个字**——利用空间局部性，拿一个字节顺带把邻居都搬上书架（接下来的访问大概率命中）。

- **命中率 h** 是生死线：平均访问时间 = h × Cache 时间 + (1−h) × 内存时间；h 从 90%→99%，平均时间差近 10 倍；
- **写策略**：写命中时——**写直达（write-through）**同时写 Cache 与内存（简单、一致但慢）；**写回（write-back）**只改 Cache、打脏标记，被换出时才写回内存（快、需脏位）。

## 3.3 映射方式：书架格子的分配规则

内存块远多于 Cache 行，内存块可以放哪一格？三种映射：

| 方式         | 规则（比喻）                               | 优缺点                                                 |
| ------------ | ------------------------------------------ | ------------------------------------------------------ |
| **直接映射** | 每块只能进固定一行（`行号 = 块号 % 行数`） | 硬件最简；冲突大（两块抢一行互相踢）                   |
| **全相联**   | 任意块放任意行                             | 最灵活、命中率高；查找全表比、硬件贵（只适合小 Cache） |
| **组相联**   | 先分组（块号定组），组内随便放             | **折中主流**：N 路组相联 = 每组 N 行供选择             |

比对命中还要靠**标记（tag）**（存块的"身份牌"）+ **有效位**；两块数据"同名同姓"时 tag 区分。冲突不命中、容量不命中、强制不命中（3C 缺失分类）是调优 Cache 的框架。

## 3.4 局部性落地：写代码的性能启示

📌 **比喻**：同一本书先通读一章再下一章（顺序）比跳着翻页快得多——书架搬运次数天差地别。

```c
// 空间局部性：顺序访问，每次 miss 带回 64 字节全用上 —— 快
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        sum += a[i][j];        // 按行走（C 行优先）

// 跳着访问（按列走）：每 4KB 才命中一次附近 —— 慢数倍
for (j = 0; j < N; j++)
    for (i = 0; i < N; i++)
        sum += a[i][j];        // 每步跳一整行
```

更多落点：**结构体按访问热排序字段**（热字段同 Cache 行）、**循环内尽量少 new 对象**（空间局部性）、**避免大数组穿插访问**（冲突缺失）。Python 教程"数组比链表缓存友好"、Java 教程 ArrayList 比 LinkedList 快——根源全在此章。

## 3.5 与虚拟内存的镜像关系

|        | Cache               | 虚拟内存（OS 卷 o04）    |
| ------ | ------------------- | ------------------------ |
| 层次   | Cache ↔ 内存        | 内存 ↔ 磁盘              |
| 块     | 行（64B）           | 页（4KB）                |
| 映射   | 直接/组相联/全相联  | 页表（全相联式任意映射） |
| 未命中 | 访内存              | 缺页中断，从磁盘调       |
| 写策略 | 写直达/写回         | 写回（脏页）             |
| 加速   | TLB? 不——Cache 自身 | TLB（页表的 Cache）      |

**同一种思想在两级存储间复用**——"小而快缓冲大而慢，靠局部性命中"是计算机体系的第一设计模式。

## 自测题

1. 为什么 Cache 搬整块（64B）而不是一个字？（空间局部性：邻居大概率马上被访问，一次搬运多次命中）
2. 写回策略需要哪个额外位？（脏位/修改位——标记该行与内存不一致，换出时才写回）
3. 两维数组按行遍历与按列遍历为何性能差数倍？（行优先存储的数组按行访问=空间局部性满血；按列=每次跳一整行，Cache 命中率暴跌）

# c04 指令系统与 CPU

> 本章目标：CPU 的大脑如何工作——指令长什么样、怎么寻址数据、一条指令的执行周期、以及流水线如何让 CPU 快如闪电（还有它为什么"冒烟"）。

---

## 4.1 指令系统：CPU 的母语

📌 **比喻**：CPU 只懂**固定句式的短句**："把 3 号抽屉的东西拿过来""把它和 5 号抽屉的相加""结果放回 3 号"。所谓高级语言，最终都被翻译成亿万条这样的短句。

📐 **定义**：一条机器指令 = **操作码（opcode：干什么）+ 地址码（operand：对谁干）**。

```asm
ADD R1, R2, R3     ; R3 = R1 + R2（寄存器-寄存器）
LOAD R1, [0x1000]  ; 从内存地址 0x1000 取数到寄存器 R1
STORE R1, [0x2000] ; 反向存回
JMP 0x0040         ; 跳转
BEQ R1, R2, 0x60   ; 相等则跳（条件分支）
```

**寄存器**是 CPU 内部的超高速暂存格（通用寄存器存数据、PC 存下条指令地址、状态寄存器存标志位）——数据必须**先搬进寄存器才能被 ALU 加工**。两大指令集设计哲学：**CISC**（x86：指令多而复杂，一条指令干很多事）vs **RISC**（ARM/RISC-V：指令少而规整、等长，利于流水线——手机芯片的天下）。

**寻址方式**（指令怎么找到操作数）：立即寻址（数就在指令里）、直接寻址（指令里是地址）、**寄存器寻址**（在寄存器里，最快）、**寄存器间接寻址**（寄存器里存的是地址，先取地址再取数）、基址/变址（寄存器 + 偏移——数组 `a[i]` 的硬件原理！）、相对寻址（PC + 偏移——分支跳转）。

## 4.2 指令周期：一条指令的一生

```
取指（Fetch）  ：按 PC 取指令，PC 自动 +指令长度
译码（Decode） ：分析操作码——"这是加法，要 R1、R2"
执行（Execute）：ALU 运算 / 访存（可能 LOAD/STORE）
写回（Writeback）：结果写回寄存器
（访存类指令多一拍：按地址读/写内存；条件分支改 PC → 跳走）
```

**控制器**指挥这四拍：**硬布线控制器**（纯电路组合逻辑，快、难改）与**微程序控制器**（每条机器指令 = 一段微程序，灵活、慢些——c01 层次表的微程序层）。

## 4.3 流水线：洗衣服的智慧

📌 **比喻**：洗三批衣服。**串行**：洗 A→晾 A→收 A→洗 B……；**流水线**：A 在晾时 B 已经在洗、C 已进洗衣机——**每批总时间不变，但吞吐率翻数倍**（一切完成后大家都在忙）。

📐 **定义**：**指令流水线**把指令周期切成分段（经典五段：取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB），**多条指令在不同段同时推进**。理想加速比 ≈ 段数（5 段≈5 倍吞吐）。

**三种冒险（hazard）——流水线的减速带**：

| 冒险         | 情形（比喻）                                 | 解决                                                     |
| ------------ | -------------------------------------------- | -------------------------------------------------------- |
| **结构冒险** | 两指令抢同一设备（一个座位两人抢）           | 资源重复（I-Cache/D-Cache 分开）                         |
| **数据冒险** | 后指令要用前指令**还没算完**的结果           | **转发/旁路**（结果一生成就直接递给下一段）、插入气泡    |
| **控制冒险** | 分支指令不知道下一条跳哪（路还没定车往哪开） | **分支预测**（猜历史：绝大多数猜对）+ 预测错误冲刷流水线 |

**分支预测**是现代 CPU 性能之王：预测准确率 >95%，猜错则**冲刷整段流水线**（十几个时钟周期白干）——这就是"分支写成可预测模式能加速循环"的硬件根源（也是"无序数组分支比有序慢数倍"实验的答案）。

## 4.4 CISC 与 RISC、超标量

- **RISC 精髓**：指令等长规整 → 流水线友好；load/store 架构（只有取数/存数指令碰内存，运算只在寄存器间）；
- **超标量**：一拍发射**多条**指令到多个 ALU（流水线的平方）；**乱序执行**：不按程序顺序，按"数据就绪"顺序执行（硬件调度，对照 OS 调度思想）；
- **多核**：流水线榨干单核 → 横向多核并行（并发问题交给 OS/程序员，o03 的锁在这里成为刚需）。

## 易错点清单

1. PC 在**取指后**自增（不是执行后）；
2. 条件分支改变的是 **PC**——控制冒险的根源；
3. 流水线加速的是**吞吐率**而非单条指令延迟（单条指令时间反而可能更长——段间寄存器开销）；
4. "CPU 主频翻倍程序就快一倍"——忘了访存、分支预测失败、内存墙（c03）。

## 自测题

1. `a[i] = a[i] + 1` 用了哪些寻址方式？（变址寻址（基址+i×元素大小）定位、LOAD/STORE 访存）
2. 数据冒险怎么解决最快？（转发/旁路——ALU 结果直接前递，不等写回）
3. 为什么 RISC 更适合流水线？（指令等长规整、单周期化、load/store 分离——各段均衡无长尾）

# c05 总线与 IO

> 本章目标：部件之间怎么"连"（总线），以及 CPU 怎么与慢速外设共舞（IO 三种方式）。本章与 OS 卷 o05（缓冲/中断/DMA）互为表里。

---

## 5.1 总线：共享高速公路

📌 **比喻**：一条**合用的公路**——所有部件的货车共用；一次只许一列车占道（**分时使用**），谁先上（**仲裁**）要讲规矩。

📐 **定义**：**总线是连接多个部件的公共信息传输干线**，按传递内容分三类：

- **数据总线**（双向）：运数据，宽度（32/64 根）= 一次运多少位；
- **地址总线**（单向：CPU→外）：指去哪，宽度决定**寻址空间**（32 位 → 4GB，64 位 → 天文数字）；
- **控制总线**：命令与状态（读/写、中断请求、时钟）。

演进：**片内总线**（CPU 内部）→ **系统总线**（主板：内存/扩展）→ **通信总线**（机器间）。现代替代方案：PCIe（高速串行点对点"专用高速路网"取代共享公车）、内存通道（DDR）——共享总线因"大家抢一条路"成为瓶颈，被**点对点专用线路+交换**取代（思想同交换机取代集线器，计网卷 n02）。

**总线仲裁**：多设备争总线，由仲裁器定优先级（集中式：链式查询/计数器/独立请求；分布式：自旋竞争）。

## 5.2 IO 接口与三种传送方式

外设与 CPU 之间隔着**IO 接口**（翻译官 + 中转仓库：数据寄存器、状态寄存器、控制寄存器——CPU 通过读写这些寄存器控制设备，**设备寄存器也占地址空间**（端口寻址/内存映射 IO））。

CPU 与外设传数据三种方式（对照 OS 卷 o05.4，硬件视角补全）：

| 方式         | 机制                                                         | 代价                    | 适用                          |
| ------------ | ------------------------------------------------------------ | ----------------------- | ----------------------------- |
| **程序查询** | CPU 死循环查状态寄存器直到就绪                               | CPU 100% 空等           | 极简/单任务嵌入式             |
| **中断**     | 设备就绪时发中断信号，CPU 暂停当前去处理                     | 每次中断有现场开销      | 键盘/鼠标等**低速、突发**设备 |
| **DMA**      | DMA 控制器**接管总线**直接在设备↔内存搬运，CPU 完全解放，完成后一次中断 | 需 DMA 控制器与总线仲裁 | 磁盘/网卡等**高速、大块**传输 |

**中断的细节**（OS 卷 o06 的硬件底座）：**中断请求线**（IRQ）→ **中断控制器**（8259A/APIC：汇总、排队、按优先级送 CPU）→ CPU 查**中断向量表**执行处理程序。**中断嵌套**：高优先级可以打断低优先级处理（洋葱式保存现场）。

## 5.3 程序中断方式的完整时序（考试重点）

```
① CPU 执行主程序……
② 键盘按下 → 接口置状态位 → 向 CPU 发中断请求（INTR）
③ CPU 每条指令执行末尾查中断 → 有请求且未屏蔽 → 响应
④ 保护现场（PC、寄存器压栈）→ 关中断 → 查向量表 → 执行中断服务程序
⑤ 服务程序：读走键盘数据（解除请求）→ 处理 → 恢复现场 → 开中断
⑥ 中断返回指令（iret）→ 回到主程序断点处继续
```

每一步对应一个考点：**响应时机**（指令周期结束，不是任意时刻）、**现场保存**（PC 与寄存器）、**中断屏蔽**（关键代码禁打扰）。

### IO 端口编址：两种"门牌"体系

CPU 怎么区分"访问内存还是访问设备寄存器"？两套编址方案：

| 方案                              | 做法                                                   | 优缺点                                                       |
| --------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| **独立编址**（端口地址空间）      | 设备寄存器用专门地址空间 + 专门指令（x86 的 `in/out`） | 不占内存地址；但需要额外指令                                 |
| **统一编址**（内存映射 IO, MMIO） | 设备寄存器**占用内存地址段**，普通访存指令即可读写     | 无需专用指令、C 语言指针直控硬件（嵌入式常见）；但挤占内存地址、Cache 需绕开这些段 |

举例：显卡帧缓冲用 MMIO——`*(volatile uint32_t*)0xA0000 = color` 一个赋值就点亮了像素（"volatile"禁编译器优化——每次必须真读真写）。这两种编址是"操作系统写驱动"的日常知识，也是 x86 与 ARM 平台差异的经典考点。

## 5.4 通道与 IO 处理机（大型机扩展）

DMA 还要 CPU 设定"搬多少、从哪到哪"；**通道（IOP）**更进一步——**自带小型处理器和程序**，CPU 只丢一条"启动通道指令"，通道独立执行整个 IO 程序、完成后中断一次。层级递进：**查询 → 中断 → DMA → 通道**，CPU 参与度逐级下降（解放 CPU 的千年大业）。

## 易错点清单

1. 地址总线宽度与寻址空间混淆（20 根 = 1MB，2²⁰）；
2. 认为"中断一发生 CPU 立即响应"——**在指令周期边界**检查响应（c04）；
3. DMA 期间 CPU 完全没事干？（CPU 可执行不需要总线的指令——缓存的命中计算等；或被总线仲裁暂停访存，"周期挪用"）；
4. 中断服务程序里死循环/太长 → 低优先级中断与主程序全部饿死（中断服务要短小，重活交给主循环/下半部）。

## 自测题

1. 32 位地址总线寻址空间多大？（2³² = 4GB）
2. 键盘为什么用中断不用 DMA？（数据量小且突发——DMA 的搬运优势发挥不出来，中断一次一字节更划算；磁盘/网卡相反）
3. 中断响应在什么时候？（一条指令执行完毕时——不能打断指令中间）

# c06 综合：一条指令的一生

> 本章目标：把 c01~c05 的零件组装起来——跟随一条 `LOAD R1, [0x1000]` 从出生到退休的全过程，看清"程序"在硬件层的真身。附带全书速查与四门课收官。

---

## 6.1 一条指令的一生（全书串讲）

```asm
LOAD R1, [0x1000]     ; 把内存 0x1000 处的数取到寄存器 R1
```

```
① 取指：PC=0x2000 → 地址经总线发往内存 → 取回指令字 → 存入指令寄存器 IR；PC += 4
   （若指令不在 Cache：c03 未命中 → 去内存搬整块）
② 译码：控制器识别"这是 LOAD，目标 R1，地址 0x1000"
③ 取数：地址 0x1000 → 查 Cache（c03）——命中直接拿；未命中 → 发总线读请求（c05）
   → 若该页不在内存：缺页异常（OS 卷 o04 虚拟内存！VA→PA 翻译、磁盘调入）
   → DMA 可能参与搬运（c05）→ 数据到达 → 载入 R1
④ 写回/结束：PC 已指向下一条指令；流水线（c04）继续发射后续指令
```

**一条"简单"指令，横跨四门课**：它的编码是数据表示（c02）、执行是流水线（c04）、取数是存储层次（c03）、访存要过总线（c05）、缺页会惊动 OS（操作系统卷）、若数据来自网卡还要走网络栈（计网卷）。**这就是"组成原理是四门课的地基"的含义**。

## 6.2 四门基础课总串联：从敲键盘到网页显示

一次完整旅程（四门课的联合演出，复习总图）：

```
敲键盘（组成：中断 c05；OS：键盘中断处理 o06）
  ▼ 浏览器进程（OS：进程调度 o02）解析 URL
  ▼ DNS 查询（计网 n05）→ IP 报文封装（计网 n01~n03）
  ▼ TCP 三次握手（计网 n04）→ HTTP 请求发出
  ▼ 网卡收到数据 → DMA 进内存（组成 c05；OS 缓冲 o05）→ 中断唤醒进程
  ▼ 服务器侧：请求处理 → 数据库查询（数据结构：B+树索引 d04；OS：页缓存 o05）
  ▼ 响应返回 → 浏览器渲染 → 显存（DMA）→ 屏幕显示（中断/驱动）
```

**四门课的知识在你每次上网时同时在线**——这就是"基础课"的含义：它们不是四门孤立的考试科目，而是同一个真实系统的四面。
