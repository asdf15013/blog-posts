# 操作系统：学习总结

> 操作系统（OS）是**硬件之上的第一层软件**：向上给应用提供便捷的服务（系统调用），向下管理一切硬件资源（CPU、内存、外设）。本总结面向**补体系 + 查阅**：每个机制先比喻后定义，章末自测。

---

- **补体系**：按 o01→o06 顺序读——操作系统四个核心模块（处理机管理、内存管理、文件管理、设备管理）各有专章；
- **查阅**：各章对比表可直接查；附录速查大表；
- **联动**：学完可回头理解"语言教程里的一切运行时现象"（栈溢出、malloc、多线程）——OS 是它们的舞台。

## 学习心法

1. **一切为了三个矛盾**：CPU 快 vs 外设慢、内存小 vs 程序大、多任务竞争——每个 OS 机制都是为解决某个矛盾而生，记住矛盾就记住了机制；
2. **类比要落地**：餐厅/车间比喻帮你入门，但每个比喻都要"翻译回术语"（对照双轨风格）；
3. **抓并发思维**：OS 本质是"多个执行流争抢资源"的管理学——这套思维迁移到任何并发编程场景。

# o01 操作系统总览：资源管理者

> 本章目标：建立 OS 的全景图——它管什么、怎么管、应用如何请求它的服务（系统调用）。

---

## 1.1 OS 是什么

📌 **比喻**：酒店的总经理。客人（应用程序）只管提需求（"我要一间房""我要订餐"），总经理负责排房、派清洁、协调后厨（硬件资源）；客人无需知道锅炉房在哪，只需打电话给前台（系统调用）。

📐 **定义**：**操作系统是管理计算机硬件资源、控制程序执行、为用户提供便捷接口的系统软件**。两大角色：

- **资源管理者**：处理机（CPU 时间）、内存、文件（外设存储）、设备（IO）——四大管理模块正好对应本书四章（o02~o05）；
- **用户接口**：命令行（shell）、图形界面（GUI）、**系统调用**（程序级接口，本章 1.3）。

三个基本特征：**并发**（多任务宏观同时）、**共享**（资源互斥共享或同时访问）、**虚拟**（一个 CPU 虚拟成多个"虚拟机"、一块磁盘虚拟成无数文件）、**异步**（进程走走停停，结果不受打断顺序影响——前提是正确同步）。

## 1.2 内核态与用户态：双Ring世界

📌 **比喻**：银行的**营业大厅**（用户态）与**金库**（内核态）。客户可以随意在大厅活动，但取钱必须通过柜台窗口（系统调用）由银行职员（内核）代办——**客户绝不许自己进金库**，否则人人都能改账本。

📐 **定义**：CPU 通过特权级别（如 x86 的 Ring0~Ring3）划分两种执行状态：

- **用户态**：应用程序运行的地方，**只能执行非特权指令**（算术、跳转），不能直接碰硬件、不能访问其他进程内存；
- **内核态**：操作系统内核运行的地方，**可执行一切特权指令**（开关中断、IO、改页表）。

**为什么分态**：保护——若应用能直接操作硬件/内存，一个 bug（或病毒）就能摧毁整个系统。分态让"危险操作"全部收口到内核，经过审核。

**态的切换**只有三条路：**系统调用**（主动）、**中断**（硬件敲门）、**异常**（程序出错，如除零/缺页）。切换有成本（保存/恢复现场、切换地址空间），所以"频繁系统调用"是性能反模式（对照编程教程：读文件用缓冲区而不是一个字节一个字节 read）。

## 1.3 系统调用：应用的"官方窗口"

📌 **比喻**：前台窗口的**点单菜单**——编号固定（read=3 号服务）、流程固定（递单→等待→取餐）。

📐 **定义**：**系统调用（syscall）是操作系统内核提供给应用程序的函数接口**，是用户态进入内核态的**唯一主动通道**。流程：

```
应用调用库函数（如 C 的 read()）
  ▼ 库把系统调用号放入寄存器，执行特殊指令（x86: syscall / 早期 int 0x80）
CPU 切换到内核态，跳转到系统调用表对应内核函数
  ▼ 内核校验参数 → 执行（可能阻塞等待磁盘）→ 结果放寄存器
CPU 恢复用户态，应用拿到返回值
```

系统调用分层视角（分类速记）：

| 类别     | 典型调用                    | 干什么                   |
| -------- | --------------------------- | ------------------------ |
| 进程控制 | fork / exec / exit / wait   | 创建、换程序、退出、收尸 |
| 文件     | open / read / write / close | 第 o05 章                |
| 设备     | ioctl / read / write        | 设备当文件读             |
| 信息     | getpid / time               | 查询                     |
| 通信     | pipe / shmget / kill        | 进程间通信（o02/o03）    |

**库函数 ≠ 系统调用**：`printf` 是库函数（内部可能调 write 系统调用）；`strlen` 纯库函数不进内核。一个"调用进不进内核"的判据：**需不需要内核特权**（碰硬件、管全局资源）。

## 1.4 OS 的四大管理模块（全书地图）

| 模块       | 管什么   | 核心问题               | 对应章           |
| ---------- | -------- | ---------------------- | ---------------- |
| 处理机管理 | CPU 时间 | 多任务谁先用 CPU？     | o02（进程/调度） |
| 内存管理   | 内存空间 | 内存不够大程序怎么办？ | o04（虚拟内存）  |
| 文件管理   | 外设存储 | 磁盘数据怎么组织与找？ | o05              |
| 设备管理   | IO 设备  | 慢设备怎么不拖死 CPU？ | o05、o06         |

学习时每个模块都问三句：**管什么资源？什么数据结构记录？（如进程的 PCB、内存的页表）什么策略分配？**——OS 就是"数据结构 + 策略"的大型应用（数据结构课程直接落地）。

## 易错点清单

1. 认为"应用程序能直接读写磁盘"——一切硬件访问必须过系统调用进内核；
2. 把库函数当系统调用（printf/gettimeofday 的实现各有千秋）；
3. 忽视系统调用开销——一次 syscall 约 1~10 μs，热循环里频繁调用是性能杀手。

## 自测题

1. 应用要读磁盘上的文件，完整的态切换路径？（用户态 → syscall 指令 → 内核态执行读盘逻辑（可能阻塞）→ 恢复用户态返回）
2. 为什么用户态不能直接访问硬件？（保护：防止错误/恶意代码破坏系统与其他进程——危险操作收口内核统一审核）
3. OS 的四个基本特征分别是什么？（并发、共享、虚拟、异步）

# o02 进程与线程

> 本章目标：搞清"程序 vs 进程 vs 线程"三个词的关系；掌握进程状态转换与调度算法；理解进程间通信（IPC）与协程。这是 OS 课程的核心章。

---

## 2.1 程序、进程、PCB

📌 **比喻**：**程序 = 菜谱**（静态的纸）；**进程 = 照着菜谱炒菜这件事**（动态的过程，占着灶台锅碗）；同一个菜谱可以同时炒三锅菜（三个进程），各用各的锅。

📐 **定义**：**进程是程序的一次执行过程，是系统进行资源分配的基本单位**。它 = **程序代码 + 数据 + 进程控制块（PCB）**。

**PCB（Process Control Block）** 是进程的"身份证+档案"——OS 管理进程的全部依据：进程 ID、状态、优先级、程序计数器（执行到哪）、寄存器现场、内存信息（页表）、打开文件表。**进程切换 = 保存当前 PCB 现场 + 换上下页表 + 载入新 PCB 现场**（上下文切换，有成本，μs 级）。

## 2.2 进程状态转换（必背图）

📌 **比喻**：外卖骑手的一天——**跑单（运行）**、**等商家出餐（就绪：万事俱备只欠 CPU）**、**等顾客取餐（阻塞：在等事件，CPU 给我也不干活）**。

📐 **五态模型**：

```
        创建 → 就绪 ⇄ 运行 → 终止
                ↑      │
                └── 等待(阻塞)
```

- **就绪（Ready）**：万事俱备，只欠 CPU——在就绪队列排队；
- **运行（Running）**：正在 CPU 上执行（单 CPU 任意时刻仅一个）；
- **阻塞/等待（Blocked）**：等某事件（IO 完成、锁、信号），**CPU 空给它也没用**；
- 关键转换：**运行→就绪**（时间片用完/被高优先级抢占，非自愿）；**运行→阻塞**（主动等 IO）；**阻塞→就绪**（事件完成）——**注意没有"阻塞→运行"这条边！** 必须先回就绪排队（高频考点）。

## 2.3 调度算法

📌 **比喻**：餐厅排单策略——先来先做（FCFS）？短的先做（SJF）？每桌限时 5 分钟轮着来（RR）？

📐 **常见调度算法**：

| 算法                | 规则                    | 优点                         | 缺点                                      |
| ------------------- | ----------------------- | ---------------------------- | ----------------------------------------- |
| **FCFS** 先来先服务 | 按到达顺序              | 简单公平                     | 短任务被长任务堵死（护航效应）            |
| **SJF** 短作业优先  | 运行时间短者先          | 平均等待时间最优（数学可证） | 长任务饥饿；时间难预知                    |
| **RR** 时间片轮转   | 队列轮转，片用完回队尾  | 响应快、公平                 | 片太小→切换开销大；太大→退化 FCFS         |
| **优先级**          | 高者先；可抢占          | 重要任务优先                 | 低优先级饥饿（解法：老化 aging 逐渐提权） |
| **多级反馈队列**    | 多个 RR 队列+优先级递降 | 综合最优（兼顾响应与吞吐）   | 复杂                                      |

**多级反馈队列**是集大成者：新任务进最高优先级队列（时间片小，快速响应）；用完片降级到下队列（时间片加倍——后台长任务慢慢磨）；高队列空才跑低队列。**它同时照顾了交互任务（快响应）与批处理任务（高吞吐）**。指标：周转时间（提交→完成）、等待时间、响应时间——不同系统目标不同（批处理重周转、交互系统重响应）。

## 2.4 线程：轻量的执行流

📌 **比喻**：一家餐厅（进程）里的**多位厨师（线程）**——共享同一厨房（内存、食材、灶台），各自炒各的菜（各自的调用栈与寄存器），但改同一本菜谱时要协调（锁，o03）。

📐 **定义**：**线程是 CPU 调度的基本单位**（进程是资源分配的基本单位——分工记忆）。同进程的线程共享：**地址空间、全局变量、打开文件**；独享：**栈、寄存器、程序计数器**。线程切换比进程切换便宜（不用换页表/地址空间）。

**进程 vs 线程对照表**（面试高频）：

|          | 进程                | 线程                       |
| -------- | ------------------- | -------------------------- |
| 定位     | 资源分配单位        | 调度执行单位               |
| 地址空间 | 独立                | 同进程共享                 |
| 切换开销 | 大（换页表）        | 小                         |
| 通信     | 需 IPC 机制（见下） | 直接读写共享变量（需同步） |
| 崩溃影响 | 一进程崩不殃及他人  | 一线程崩通常带走整个进程   |

多进程 vs 多线程选型：要隔离稳定（浏览器每个标签一个进程）→ 多进程；要共享数据、切换轻快（Web 服务器工作线程）→ 多线程。

### 进程间通信（IPC）

**为什么要专门机制**：进程地址空间隔离，互相看不见对方的变量——必须借"双方都可达"的公共渠道：

| IPC             | 原理（比喻）           | 特点                                         |
| --------------- | ---------------------- | -------------------------------------------- |
| **管道 pipe**   | 一根水管：一端写一端读 | 单向、亲缘进程（父子）；命名管道可跨进程     |
| **消息队列**    | 传送带的包裹箱         | 有格式、可持久、按类型取                     |
| **共享内存**    | 两家共用的公共仓库     | **最快**（零拷贝，直接读写）；需配信号量同步 |
| **信号 signal** | 门铃/警报              | 异步通知（Ctrl+C 发 SIGINT）                 |
| **socket**      | 电话                   | **跨主机**通信（网络编程基础）               |

## 2.5 协程：用户态的"线程"

📌 **比喻**：一个厨师（单线程）同时炖三锅汤——在 A 锅等待间隙去搅 B 锅，**自己主动切换**，不需要总经理调度。

📐 **定义**：**协程是用户态的轻量"线程"**——切换由**程序自己控制**（yield/await 主动让出），不进内核、无上下文切换开销，一个线程可承载成千上万个协程。代价：**协作式**——没人抢 CPU，一个协程死循环就卡死整线程；且本质单线程内并发，**多核加速需多线程+多协程**。适用：**IO 密集**（Python asyncio、Go goroutine、Java 虚拟线程同属此家族——它们都是"等待时让出"思想的实现）。

## 易错点清单

1. "阻塞→运行"这条不存在的边（必经就绪）；
2. 时间片轮转中"时间片越快越好"——太小则切换开销占比过大，太大则响应变差（要平衡）；
3. 认为线程越多越快——CPU 密集任务线程数 ≈ 核数即可，多了切换白费（IO 密集另说）；
4. IPC 里共享内存"最快"但"不同步"——快和险并存，必须配信号量。

## 自测题

1. 进程从阻塞直接到运行对不对？（错——必经就绪队列）
2. 同进程两线程共享什么、独享什么？（共享地址空间/全局数据/打开文件；独享栈/寄存器/PC）
3. RR 时间片设为无穷大退化为？（FCFS）

# o03 并发与死锁

> 本章目标：并发世界的两大问题——**竞态**（谁先改的？）与**死锁**（谁都别想动），以及对应的解决方案。学完本章，"多线程编程为什么要锁"将从咒语变成常识。

---

## 3.1 竞态条件：一步操作三步走

📌 **比喻**：两人同时往同一个账户转账——各自"查余额 100 → 加 50 → 写回 150"，第二个人的写回**覆盖**了第一个人的结果，100 元凭空消失。

📐 **定义**：**竞态条件（race condition）**：多个执行流并发访问共享资源，**结果依赖执行顺序**。根源：看似原子的 `count++` 实际是"读→加→写"三步，交错执行即丢失更新。

**临界资源**：一次仅允许一个进程使用的资源（打印机、共享变量）。**临界区（critical section）**：访问临界资源的代码段。临界区管理四原则：**空闲让进、忙则等待、有限等待、让权等待**（进不去时释放 CPU 别干等）。

## 3.2 互斥方案：锁的家族

**① 互斥锁 mutex**：进临界区前上锁，出来解锁；拿不到就睡（阻塞）。
📌 比喻：单人间卫生间的门锁——有人里面，外面锁上等。
**② 自旋锁 spinlock**：拿不到就**原地空转重试**（不睡）。
📌 比喻：明知里面的人马上出来，站在门口盯着门不走。
选型：**临界区极短 → 自旋**（省下睡眠/唤醒开销）；**临界区长 → 互斥锁**（空转纯烧 CPU）。
**③ 读写锁**：读读共享、写写互斥、读写互斥——读多写少场景吞吐翻倍。

现代硬件补充：**原子指令**（compare-and-swap，CAS）由 CPU 一条指令完成"比较并交换"，无锁数据结构的地基（AtomicInteger 之类的底层）；** Peterson 算法**则是纯软件互斥的经典（考试用，工程少用——原子指令更实用）。

## 3.3 信号量与 P/V：万能交通灯

📌 **比喻**：停车场入口的**电子计数屏**——显示剩余车位；车到时若剩余为 0 则在门口排队，走一辆（释放）放一辆（等待队列头）。

📐 **定义**：**信号量（semaphore）是一个整数值 S + 两个原子操作**：

- **P（wait/down）**：`S--`；若 S < 0 则阻塞；
- **V（signal/up）**：`S++`；若 S ≤ 0 则唤醒一个等待者。

两大用法：

1. **互斥**：S 初值 1——进临界区 P，出 V（这就是个锁）；
2. **同步/资源计数**：S 初值 = 资源数（5 台打印机 S=5）——P 申请、V 归还；还可做**事件通知**（A 做完 V 一下，B 在 P 等着）。

### 经典模型：生产者-消费者

📌 **比喻**：厨师（生产者）往窗口出餐，服务员（消费者）取餐，中间一个**容量有限的传菜台**。

```
信号量：mutex = 1（互斥传菜台）；empty = N（空位数）；full = 0（已放餐数）

生产者：P(empty) → P(mutex) → 放餐 → V(mutex) → V(full)
消费者：P(full)  → P(mutex) → 取餐 → V(mutex) → V(empty)
```

**P 的顺序不能颠倒**（先 P(mutex) 再 P(empty) 会在"台满"时抱着锁睡觉 → 死锁）。这个模型是**一切缓冲区问题**（打印队列、消息队列）的母题。

## 3.4 死锁：四手相握的僵局

📌 **比喻**：两个筷子党——每人抓住一根筷子等对方松手，谁都吃不上饭。四人打牌各等下家出牌（循环等待）。

📐 **定义**：**死锁是多个进程互相等待对方持有且不释放的资源，导致都无法推进**。**四个必要条件**（缺一不可——破坏任意一个即可防死锁）：

1. **互斥**：资源一次只能一人用；
2. **请求并保持**：握着筷子还要再拿另一根；
3. **不可剥夺**：不能强行掰开手；
4. **循环等待**：等待链成环。

**处理策略**：

- **预防**（破坏条件）：一次性申请全部资源（破 2）；资源有序分配——所有人按编号顺序申请（破 4）——简单实用；
- **避免**：**银行家算法**——像谨慎的银行家放贷：分配前检查"分配后是否存在安全序列"（每个进程都能顺利完成），不安全就不分配（动态避免）；
- **检测与解除**：放任发生 → 定期检测资源分配图成环 → 解除（剥夺资源/回滚/杀进程）；
- **鸵鸟策略**：假装没事（多数通用 OS 的现实选择——死锁罕见且预防代价高，崩了重启）。

## 3.5 与并发编程的对接

本章概念在编程语言里的落点（对照语言教程）：mutex → Java synchronized / Python threading.Lock；信号量 → Semaphore；生产者消费者 → BlockingQueue / 条件变量；原子指令 → AtomicInteger。**学了 OS 再写多线程代码，每个 API 都有出处**。

## 易错点清单

1. P/V 顺序错误（先 mutex 后资源信号量）→ 死锁；
2. 以为死锁四条件是"充分条件"——是**必要条件**（全满足才可能死锁，破坏任意一个则不可能）；
3. 自旋锁用在长临界区——CPU 空转纯浪费；
4. 银行家算法需要**预知最大需求量**——理想化假设是它的考场常考点。

## 自测题

1. 生产者-消费者中 P(empty) 与 P(mutex) 顺序颠倒会怎样？（可能死锁：持有 mutex 却等空位，生产者被 mutex 挡住无法腾位）
2. 死锁四条件破坏法各举一例？（互斥：把独占资源改共享技术如假脱机；请求保持：一次性申请；不可剥夺：可抢占调度；循环等待：资源有序分配）
3. 读多写少场景用什么锁收益最大？（读写锁）

# o04 内存管理：虚拟内存与分页

> 本章目标：回答三个问题——程序怎么"看到"内存？内存不够大程序怎么跑？数据换了位置怎么找回来？核心答案是**虚拟内存 + 分页**。

---

## 4.1 两种朴素方案及其失败

**方案 1：连续分配**（给每个进程一整块连续内存：固定分区/动态分区）。
📌 比喻：影院按团队包场，一队必须坐**连座**。
问题：**碎片**——固定分区产生内碎片（分区块内浪费）；动态分区产生**外碎片**（零散小块加起来够用却连不成片）。

**方案 2：覆盖/交换**：程序自己分段轮流装入（覆盖）；OS 把不活跃进程整体换出到磁盘（交换 swap）。
问题：全靠程序员手动规划（覆盖）太痛苦；整进程换入换出粒度太粗。

**失败指路**：需要一种"进程以为自己有连续大内存，物理上却可拆散摆放"的机制——**虚拟内存**。

## 4.2 虚拟内存：许诺的宫殿

📌 **比喻**：**吹牛的艺术**。每个进程对用户吹牛："我有整整 4GB 私人大内存，地址 0 到 2³² 随便用"——实际上背后只有真实的几 GB 物理内存 + 磁盘兜底。吹牛成功的秘诀是一本**翻译账本（页表）**：进程说的每个地址，OS 现场翻译成真实位置。

📐 **定义**：**虚拟内存为每个进程提供独立的、远大于物理内存的虚拟地址空间**。程序使用**虚拟地址（VA）**，访问时由硬件（MMU，内存管理单元）+ 页表翻译成**物理地址（PA）**。三大收益：

1. **隔离**：各进程地址空间独立（A 进程的地址 0x1000 ≠ B 进程的 0x1000）——安全；
2. **超卖**：虚拟空间可远大于物理内存（不常用的页放磁盘）——大程序小内存也能跑；
3. **共享**：两进程的虚拟页可映射到同一物理页（共享库只存一份）。

## 4.3 分页：把一切切成标准集装箱

📌 **比喻**：不再要求连座（消灭外碎片），而是把**影院和观众都切成标准座位单位**——任何观众占任意分散的座位都行，只要账本记着"观众 3 号坐第 5 排 7 座"。

📐 **定义**：**分页**把虚拟地址空间与物理内存都切成固定大小的**页（page，通常 4KB）**。虚拟地址 = **页号（页表索引）+ 页内偏移**。**页表**记录每页的映射：虚拟页号 → 物理页框号 + 状态位（在内存吗？可写吗？访问过吗？）。

翻译流程（MMU 硬件完成）：

```
VA = [页号 p | 偏移 d]
① 查页表第 p 项 → 物理页框号 f（+ 校验权限位）
② PA = f × 页大小 + d          ← 偏移不变，只换"哪个 4KB 块"
```

分页消灭了**外碎片**（页任意散放）；**内碎片**仍在但很小（最后半页浪费 ≤ 4KB/进程）。

### 页表与 TLB：翻译的加速

**问题**：页表本身很大（4GB / 4KB = 100 万项），每条访存都要查表 → 变慢一倍。
**解法 1：TLB（快表）**——页表的**硬件缓存**（对照组成原理 Cache 思想）：热点映射存 TLB，命中则一次直达（命中率 >90%，靠**局部性**，见 4.5）。
**解法 2：多级页表**——页表本身也分页，用不到的二级表不建（稀疏地址空间的省钱术，x86-64 四级页表）。

## 4.4 缺页中断：要的页不在内存！

📌 **比喻**：翻书翻到第 50 页发现是**夹着一张纸条**："此页在图书馆，凭条去取"。你（CPU）暂停、管家（OS）去图书馆（磁盘）把书页取回、更新账本、再让你继续——你本人毫无察觉。

📐 **定义**：访问的页不在物理内存时，MMU 触发**缺页中断（page fault）**：OS 从磁盘调入该页；物理内存满了则**页面置换**——选一页" victim"踢出（改过的先写回磁盘）。现代 OS 按需调页（demand paging）让"启动"只装必须的页，其余按缺页慢慢调——**启动快、内存省**的来源。

### 页面置换算法（考点密集）

| 算法                       | 规则（比喻）                                       | 优缺点                                         |
| -------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| **FIFO**                   | 最先来的先走（先来的先请走）                       | 简单；有 **Belady 异常**（帧数增多缺页反增！） |
| **OPT**（理论最优）        | 走"以后最久不用"的（先知模式）                     | 无法实现，只作评价基准                         |
| **LRU**                    | 走"最近最久未用"的（刚用过的可能还会用）           | 近似 OPT、代价较高（需记录访问时间/栈）        |
| **Clock（时钟/二次机会）** | 指针转圈，访问位 1 给第二次机会清 0 跳过，0 则换出 | LRU 的廉价近似（访问位硬件自带）               |

**抖动（thashing）**：物理内存太小，刚换出的页马上又要——CPU 全在换页，程序近乎卡死。解法：增内存、降并发、按工作集（working set）分配。

## 4.5 局部性原理：一切的底层信仰

📌 **比喻**：你读书只反复翻几章，不会整本均匀翻——**刚翻过的章节接下来还会翻**（时间局部性），**旁边的章节也常被翻**（空间局部性）。

📐 **定义**：**时间局部性**——刚被访问的信息，近期很可能再次被访问（循环变量）；**空间局部性**——某地址被访问，其附近地址 soon 被访问（数组顺序遍历）。**局部性是整个存储层次体系成立的根基**：Cache、TLB、预读、分页全靠它命中率才高（组成原理 c03 再次回收）。写代码的启示：顺序访问数组远快于跳着访问（缓存友好）。

### 动态分区分配算法（连续分配时代的策略）

虚拟内存出现前，动态分区如何挑空位？四策略（考试常考对比）：

| 算法                   | 规则（比喻）             | 特点                                         |
| ---------------------- | ------------------------ | -------------------------------------------- |
| **首次适应 First Fit** | 从头找第一个装得下的     | 简单、综合表现好（低地址碎片被快速用掉）     |
| **下次适应 Next Fit**  | 从上次停的地方继续找     | 分布更均匀                                   |
| **最佳适应 Best Fit**  | 挑**装满后剩余最小**的洞 | 省大块；但产生大量极小碎片（"最佳"名不副实） |
| **最坏适应 Worst Fit** | 挑**剩余最大**的洞       | 切剩的部分仍可用；大作业容易没家             |

（快速搭子：这四种是"选择策略"——对比 OS 调度算法的 FCFS/SJF，同为"资源分配策略"题型的两种经典。）

## 4.6 内存管理全家对比

| 技术     | 思路                        | 碎片     | 硬件支持  |
| -------- | --------------------------- | -------- | --------- |
| 固定分区 | 预先切好块                  | 内碎片   | 无        |
| 动态分区 | 按需连续分配                | 外碎片   | 无        |
| **分页** | 定长页+页表                 | 内碎片小 | MMU+TLB   |
| 分段     | 按逻辑段（代码/数据）不定长 | 外碎片   | 段表      |
| 段页式   | 先分段再分页                | 内碎片小 | 段表+页表 |

## 自测题

1. 虚拟地址到物理地址，哪部分不变？（页内偏移）
2. 缺页中断属于"内部中断/异常"还是"外设中断"？处理完进程会怎样？（异常/内中断；进程暂停，页面调入后**从引起缺页的指令重新执行**）
3. FIFO 的 Belady 异常指什么？（分配帧数增多缺页次数反而增加——LRU/OPT 无此现象）
4. 频繁缺页导致系统卡死，这个现象叫什么、怎么解决？（抖动；增内存/降多道程序度）

# o05 文件系统与 IO

> 本章目标：磁盘上的数据怎么组织成"文件"？进程怎么读写它们而不拖慢 CPU？——文件管理与 IO 管理两件套。

---

## 5.1 文件与文件系统

📌 **比喻**：仓库管理员不看"第几扇区第几磁道"，只看**货物单**——"3 号仓第 2 架有 500 箱苹果"。**文件系统 = 把物理存储抽象成"名字可查、可读写的文件"的管理层**。

📐 **定义**：**文件是具有名字的相关信息集合**（字节流视角：Unix 一切皆文件——普通文件、目录、设备、管道都是文件）。文件系统负责：命名（目录）、定位（映射到磁盘块）、分配、保护（权限）、回收。

文件的逻辑结构（用户视角）：字节流（Unix 通吃）或记录式（老系统）；**物理结构**（磁盘视角）：连续分配（快但碎片）、**链接分配**（FAT：每块存下一块号）、**索引分配**（inode：一册"块号目录"）。

## 5.2 inode：文件的户口本

📌 **比喻**：**档案编号系统**。每个文件（档案）有一个**户口（inode）**，记录它的全部属性和"材料存放的柜号列表"；文件名只是**户口的别名**，多个别名（硬链接）可指向同一户口。

📐 **定义（Unix inode 体系）**：

- **inode** 存：文件大小、权限、属主、时间戳、**数据块指针**——**唯独不存文件名**；
- **目录**本身也是文件：内容是"文件名 → inode 号"的映射表；
- **硬链接**：`ln a b`——两个名字指向**同一 inode**（同一文件的两个别名），删一个名字不减数据；
- **软链接（符号链接）**：`ln -s`——一个**存路径字符串的新文件**（指向名字而非 inode），可跨文件系统，原文件删除则它成"悬空链接"。

数据块指针的三级策略：前 12 个**直接指针**（小文件直查）+ 一级间接指针（指针块里存指针）+ 二级/三级间接——小文件快、大文件也能存（对照 d04 的多级页表思想：稀疏时空降、需要的才建）。

## 5.3 目录与路径

📌 **比喻**：目录是**抽屉里的索引卡**；路径是"从抽屉根开始念的完整路线"。

- 绝对路径 `/home/user/file`（从根出发）；相对路径 `./file`（从当前目录）——`.` 本目录、`..` 上一级；
- 查找 `cat a/b/c.txt`：从当前目录的目录文件查 a → a 的目录文件查 b → ……**逐级下钻**（名字解析）；
- 挂载（mount）：把一个文件系统接到目录树上某个"挂载点"——多块磁盘/U盘 融合成一棵树。

## 5.4 设备管理与 IO：慢设备不拖死 CPU

📌 **比喻**：CPU 是性急的经理，IO 设备（磁盘/网卡）是慢悠悠的供应商。管理方式进化：

| 方式                    | 机制（比喻）                                                 | 评价                                         |
| ----------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| **轮询**                | 经理每隔一分钟打电话催一次                                   | 简单；大量空转浪费 CPU                       |
| **中断**                | 供应商干完主动打电话                                         | CPU 不空等；每次中断有开销，高频小数据不划算 |
| **DMA**（直接存储访问） | 经理授权供应商**直接把货送进仓库**，全程不叫经理，只在全部完成时来一次电话 | 大块数据传输最优：CPU 完全解放               |

**DMA（Direct Memory Access）** 是现代大块 IO 的标配：设备控制器直接与内存互传，CPU 只发启动命令、收完成中断。设备驱动程序（driver）负责把统一的 OS 接口翻译成设备私有指令——"设备即文件"（一切皆文件）意味着 read 磁盘和 read 网卡走同一套系统调用（o01 的呼应）。

## 5.5 缓冲与零拷贝

**为什么缓冲**：磁盘按块（4KB）读写，进程按字节要——**缓冲区（buffer/cache）**攒单成批、复用热点数据：

- **读缓冲**：读一个字节实际读了整块，下次同块直接命中（局部性！）；
- **写缓冲**：攒一批一次性刷盘（延迟写——代价：断电丢未刷数据）。

**零拷贝**（zero-copy）案例——发一个文件给网卡：

```
传统：磁盘 →（DMA）→ 内核缓冲 →（CPU 拷贝）→ 用户缓冲 →（CPU 拷贝）→ socket 缓冲 →（DMA）→ 网卡
      四次拷贝、四次态切换
零拷贝（sendfile）：磁盘 →（DMA）→ 内核缓冲 →（DMA 直达）→ 网卡
      零次 CPU 拷贝——大文件传输（下载服务、Kafka）性能翻倍
```

零拷贝 = **减少 CPU 参与的数据搬运次数**——Web 服务器、消息队列的性能奥秘之一（Kafka 高吞吐的秘密武器）。

## 易错点清单

1. 硬链接 vs 软链接混谈（硬=同 inode 别名；软=存路径的新文件）；
2. 删除文件=数据立即消失？（只是名字与 inode 链接数减一，链接数归零才回收块——数据恢复工具的原理）；
3. 以为 read/write 直接操作磁盘（中间隔两层缓冲：OS 页缓存 + 设备缓冲，`fsync` 强制落盘）；
4. "零拷贝=一次拷贝都没有"——是零次 **CPU** 拷贝（DMA 拷贝仍在）。

## 自测题

1. 硬链接数是什么意思？`rm` 后数据何时真正释放？（指向该 inode 的名字数；减到 0 且无进程打开时回收）
2. DMA 相比中断方式省了什么？（省去 CPU 参与数据搬运本身——CPU 只收一次完成中断）
3. 为什么读第 100 字节时 OS 实际读了 4096 字节？（块粒度 IO + 局部性预读，后续同块请求直接命中缓存）

# o06 中断与系统调用：一次请求的完整旅程

> 本章目标：把前五章的知识用"中断机制"串成一条线——从敲下键盘到屏幕显示，从调用 printf 到数据落盘。这是 OS 卷的收官章。

---

## 6.1 中断：CPU 的门铃

📌 **比喻**：经理在办公室专注干活（CPU 执行程序），**门铃**（中断信号）一响，他记下进度（保存现场），去处理来访（中断处理），回来接着干（恢复现场）。没有门铃，他就得每隔一分钟跑出去看有没有人找——**轮询的地狱**。

📐 **定义**：**中断是 CPU 暂停当前程序、转去执行中断处理程序、完成后返回原程序的机制**。两大类：

- **外中断（异步，硬件中断）**：来自 CPU 之外——键盘、磁盘完成、网卡包到、时钟滴答（时间片轮转的动力！）。与当前指令无关，任意时刻可来；
- **内中断（同步，异常）**：来自 CPU 正在执行的指令——除零、非法指令、**缺页**（o04）、溢出。指令自己惹的事，必须当场处理。

处理流程五步：**关中断保护现场 → 识别中断源（中断向量表：类型号→处理程序入口）→ 执行处理程序 → 恢复现场 → 开中断返回**。中断向量表 = "门铃号码 → 对应接待人员"的对照表。

**中断的意义**：并发成为可能——时钟中断驱动时间片轮转（o02 调度）、IO 完成中断唤醒阻塞进程（o05 DMA）、缺页异常驱动虚拟内存（o04）。**没有中断，现代 OS 无法存在**。

## 6.2 一次 printf 的完整旅程（串联全书）

你在程序里写 `printf("hello")`，到屏幕亮出字符，中间发生了什么：

```
① 库函数 printf：格式化 → 攒进用户态缓冲区（没满不着急进内核）
② 缓冲区满/flush → 触发 write 系统调用（o01：syscall 指令切内核态）
③ 内核把数据写入 stdio 设备的输出缓冲（o05 缓冲）→ 返回用户态（printf 立刻"完成"）
④ 稍后内核把缓冲内容经驱动程序发给显存/串口（设备驱动翻译，o05）
⑤ DMA 把数据搬进显存（o05 零 CPU 拷贝）→ 完成后发中断（o06）
⑥ 中断处理程序确认送达；字符已在屏幕上
```

五个模块全部出场：处理机管理（态切换）、内存（缓冲区）、设备（DMA/驱动）、中断（事件驱动）、系统调用（入口）。

## 6.3 一次进程创建：fork 的旅程

```
① shell 敲 ./a.out → shell 调 fork() 系统调用
② 内核：复制一个新 PCB（代码、数据、页表——写时复制 COW：先共享物理页，
   谁写才真正复制——省内存的黑科技，o04 页表的应用）
③ 子进程获新 PID，回到用户态，父子从 fork 返回点各自继续
④ 子进程 exec() 系统调用 → 换成 a.out 的程序映像
⑤ 调度器（o02）把两个进程排进就绪队列……
```

**写时复制（COW）**是"虚拟内存"与"并发"合奏的代表作：fork 瞬间不复制几十 MB 内存（共享页只读），首次写入某页时才触发缺页异常复制该页——`fork` 因此近乎免费，进程创建飞快。
