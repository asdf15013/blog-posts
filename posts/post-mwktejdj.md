# d01 绪论与复杂度分析

> 本章目标：搞清"数据结构"到底在学什么；掌握大 O 复杂度——它是贯穿全书乃至整个编程生涯的"价格标签"。

---

## 1.1 数据结构是什么

📌 **比喻**：整理衣柜。同样的衣服（数据），随手塞进袋子（乱放）和按季节分区挂好（有组织），找一件的速度天差地别。

📐 **定义**：数据结构是**相互之间存在特定关系的数据元素的集合及其在计算机中的组织与存储方式**。它由两部分构成：

- **逻辑结构**：数据元素之间的抽象关系——集合、线性（一对一）、树形（一对多）、图形（多对多）；
- **存储结构**（物理结构）：逻辑结构在内存里的落地方式——**顺序存储**（连续一片，数组）、**链式存储**（散落各处用指针牵手，链表），以及索引、散列等衍生。

**核心命题**：同一个逻辑结构可以用不同存储实现，而**存储方式决定了操作代价**——选结构就是选代价（对照本书心法"先想存再想算"）。

## 1.2 算法与它的五个特性

📌 **比喻**：菜谱。食材（输入）按步骤（指令）做成菜（输出）；好菜谱步骤明确、任何厨师照做结果一致、有限步骤内出锅。

📐 **定义**：算法是**求解特定问题的有限指令序列**，满足五特性：**有穷性**（有限步内结束）、**确定性**（每步无歧义）、**可行性**（每步可基本实现）、**输入**（零个或多个）、**输出**（至少一个）。评价维度：**正确性、可读性、健壮性（抗非法输入）、高效性**（时间+空间）。

## 1.3 大 O 复杂度：算法的价格标签

📌 **比喻**：不是问"这道菜要做几分钟"，而是问"客人翻倍后，做饭时间翻几倍"。前者随火候变化没有意义，后者才反映菜谱本身的效率。

📐 **定义**：**渐进时间复杂度** T(n) = O(f(n))：当问题规模 n 趋于无穷时，算法基本操作次数的**增长数量级**上界。只保留最高阶项、去掉系数：`3n² + 5n + 2 → O(n²)`。

常见阶从快到慢（n=10⁶ 时粗略耗时感受）：

| 复杂度     | 名称     | 典型场景               | n=10⁶ 感受       |
| ---------- | -------- | ---------------------- | ---------------- |
| O(1)       | 常数     | 数组下标访问、哈希查找 | 瞬间             |
| O(log n)   | 对数     | 二分查找               | 瞬间（约 20 步） |
| O(n)       | 线性     | 遍历一遍               | 几毫秒           |
| O(n log n) | 线性对数 | 高效排序               | 几十毫秒         |
| O(n²)      | 平方     | 双重循环、冒泡         | 约 11 天！       |
| O(2ⁿ)      | 指数     | 穷举子集               | 宇宙热寂         |

记忆锚点：**对数 = 每步砍一半；平方 = 两层套娃；指数 = 每层翻倍**。

## 1.4 四种复杂度口径

📌 **比喻**：通勤时间。"最好 20 分钟（一路绿灯）"、"最坏 2 小时（大暴雨）"、"平均 40 分钟"、"早高峰天天 40 分钟（常态）"。

📐 **定义**：

- **最好情况** Ω：最幸运输入下的下界；
- **最坏情况** O：最倒霉输入下的上界——**工程上默认讨论它**（要按最坏做保障）；
- **平均情况** Θ：所有输入等概率出现时的期望；
- **均摊（摊还）**：一系列操作的总代价摊到每次——典型：**动态数组扩容**，偶尔一次 O(n) 的搬家，均摊到每次 append 仍是 O(1)（因为翻倍扩容让"搬家的频率"越来越低）。

易错点：**O(1) ≠ 快**，O(n²) ≠ 慢——复杂度说的是"增长趋势"，n=10 时 O(n²) 完全可能比 O(n log n) 快。它只在 n 大时说话才有分量。

## 1.5 空间复杂度与"原地"

空间复杂度 S(n)：算法**额外**占用的存储随 n 的增长量级。原地（in-place）算法 = 额外空间 O(1)，如冒泡排序只在原数组换位置；归并排序需要 O(n) 辅助数组，不是原地。**时间与空间经常可以互换**：缓存/预处理用空间买时间（哈希表就是典型——多花内存换 O(1) 查找）。

## 易错点清单

1. 忽略循环里的隐藏成本：`while (n) { n /= 2; }` 是 O(log n) 不是 O(n)；
2. 递归复杂度只算一层：递归调用树的总代价 = 每层代价 × 层数；
3. 把 O(2n) 写成 O(2n)——**系数不算**，就是 O(n)；
4. 认为 O(log n) 的"log"底数重要——底数是常数因子，O(log₂n)=O(log₁₀n)，底数随便。

## 自测题

1. `for (i=0;i<n;i++) for (j=i;j<n;j++)` 的时间复杂度？（内层从 i 到 n，共 n+(n-1)+…+1 = n(n+1)/2 次 → **O(n²)**）
2. 为什么说"动态数组 append 是均摊 O(1)"？
3. 某算法最好 O(n)、最坏 O(n²)——它可能是哪种算法？（如冒泡/插入排序：输入已有序则只扫一遍）

# d02 线性结构：数组、链表、栈、队列

> 本章目标：掌握四种线性结构的存储与代价对比——这是所有后续结构的积木。

---

## 2.1 数组 vs 链表：集装箱 vs 寻宝游戏

📌 **比喻**：数组是**集装箱仓库**——所有货位编号连续，报编号直达；链表是**寻宝游戏**——每个宝箱里只有下一站的地址，必须一箱箱摸过去。

📐 **定义**：

- **顺序存储（数组）**：元素占**连续内存**，地址 = 首地址 + i × 元素大小，所以**随机访问 O(1)**；但插入/删除需移动后续元素 **O(n)**，且容量需连续空间（扩容要整体搬家）；
- **链式存储（链表）**：节点 = **数据域 + 指针域**，散落在任意位置，靠指针串联。访问第 i 个必须从头走 **O(n)**；但插入/删除只需改指针 **O(1)**（前提：已站在位置上）。

| 操作              | 数组                   | 单链表                     |
| ----------------- | ---------------------- | -------------------------- |
| 随机访问 i        | **O(1)**               | O(n)                       |
| 头部插入/删除     | O(n)                   | **O(1)**                   |
| 尾部插入          | O(1)（摊还，若留容量） | O(1)（带尾指针）           |
| 已定位处插入/删除 | O(n)（要挪人）         | **O(1)**（只改指针）       |
| 内存              | 连续、缓存友好         | 分散、每节点多一个指针开销 |

选型口诀：**读多写少用数组，频繁增删用链表**；现代 CPU 还有一票：数组的连续内存对 **CPU 缓存**（组成原理 c03）极其友好——实践里数组（动态数组）出场率远高于链表。

链表变体：**双向链表**（前后都牵手，可倒走、删除已知节点 O(1) 不用找前驱）、**循环链表**（尾接头，约瑟夫环问题）、**哑头节点**（dummy head：统一"改头节点"与"改中间节点"的代码路径，消掉边界特判——链表题的第一技巧）。

## 2.2 栈：叠盘子

📌 **比喻**：餐厅摞盘子——只能从顶上放、从顶上拿，最后放的最先被拿走。

📐 **定义**：**栈（stack）是仅在一端（栈顶）进行插入（push）与删除（pop）的线性表**，遵循 **LIFO**（Last In, First Out，后进先出）。核心操作 O(1)；判断栈空 `top == -1`（顺序栈）、栈满溢出。

四个经典应用：

1. **函数调用**：每调一个函数压一帧（局部变量），返回弹一帧——递归过深 = 栈溢出（StackOverflow，对照编程语言教程的递归章）；
2. **括号匹配**：左括号压栈，遇右括号弹栈比对——编辑器/编译器的基本功；
3. **表达式求值**：中缀转后缀（逆波兰）、后缀一遍扫描求值，双栈（数字栈+运算符栈）处理优先级；
4. **浏览器后退/编辑器撤销**：每步操作压栈，撤销即 pop。

变体：**共享栈**（两栈共用一个数组，栈顶相向生长，省空间）、**链栈**（无容量上限）。

## 2.3 队列：排队买票

📌 **比喻**：银行取号排队——只能队尾进、队头出，先来先服务。

📐 **定义**：**队列（queue）是队尾入队（enqueue）、队头出队（dequeue）的线性表**，遵循 **FIFO**（First In, First Out）。**循环队列**用取模把数组首尾接成环：`rear = (rear + 1) % maxSize`，解决"假溢出"（头部出队后前端空着却报满）；判满与判空的区分用**牺牲一格**（`(rear+1)%size == front` 为满）或**计数器**。

经典应用：**任务调度**（操作系统就绪队列）、**消息缓冲**、**BFS 的候访队列**（d05）。双端队列 deque（两头都能进出）同时具备栈与队列能力——语言标准库的 deque 内部是"分块数组"而非纯链表（兼顾两端 O(1) 与缓存友好）。

## 2.4 对比总表（查阅用）

| 结构   | 逻辑      | 插入/删除     | 访问      | 典型应用             |
| ------ | --------- | ------------- | --------- | -------------------- |
| 数组   | 线性·顺序 | 中间 O(n)     | 随机 O(1) | 查表、缓存友好遍历   |
| 单链表 | 线性·链式 | 已定位处 O(1) | 顺序 O(n) | 频繁增删、大小未知   |
| 栈     | LIFO      | 栈顶 O(1)     | 只见栈顶  | 函数调用、括号、撤销 |
| 队列   | FIFO      | 两端 O(1)     | 只见队头  | 调度、缓冲、BFS      |

## 易错点清单

1. 链表题不画图直接写指针——**画图！** 尤其删头节点、反转链表；
2. 循环队列判满用 `rear == front`（与判空撞车）——必须牺牲一格或计数；
3. 栈混洗判断：入栈序列 1,2,3 时出栈序列不可能出现 "3,1,2"（3 先出则 1,2 必须已压着）——合法出栈序列判定的核心技巧。

## 自测题

1. 数组插入删除 O(n)，链表 O(1)——那为什么动态数组更常用？（缓存友好 + 尾部操作均摊 O(1)，真实负载多为尾部追加）
2. 用两个栈实现队列，说出操作代价。（in 栈接货，out 栈出货；out 空时把 in 整体倒过去，均摊每次操作 O(1)）
3. 循环队列容量 8，front=3, rear=1，元素个数？（(1-3+8)%8 = 6 个）

# d03 哈希与串：哈希表、字符串匹配

> 本章目标：吃透哈希表的原理与冲突处理（现代开发的头号结构）；掌握 KMP 的思想与朴素匹配。

---

## 3.1 哈希表：寄存牌取衣

📌 **比喻**：衣帽间。把外套（键）交给柜员，柜员用固定口诀算出格子号（哈希函数），发你一张牌（记住格子号）；凭牌（键再算一遍）直接去格子取——**不用翻遍所有格子**。

📐 **定义**：**哈希表（散列表）以哈希函数 h(key) 把键映射到数组的下标，实现期望 O(1) 的查找、插入、删除**。理想下每个键落到不同格子（完美哈希），现实中键的数量/分布往往超过格子数，于是**冲突不可避免**——哈希表设计的核心就是**冲突处理**。

### 冲突处理两大家族

**① 链地址法（拉链法）**：每个格子挂一条链表，冲突的键依次串在同一条链上。查找 = 先定位格子再走链。优点：删除方便、负载可超过 1；缺点：指针开销、缓存不友好。Java 的 HashMap、Python dict 的演进版都是此路线。

**② 开放寻址法**：冲突了就按探测序列找下一个空格：

- **线性探测**：依次 +1，+2……——简单但会"堆积"（数据连成片，越长越容易撞）；
- **平方探测**：+1², −1², +2²……把堆积打散；
- **再哈希**：换一个哈希函数重新算。

优点：连续内存、缓存友好（PHP 数组即此路线）；缺点：**删除麻烦**（不能真删，要打"墓碑"标记，否则会截断探测链）、负载因子必须压低。

### 负载因子与扩容

**负载因子 α = 元素数 / 格子数**。α 越大冲突越频繁：链地址法通常 α>1 后性能渐降（Java HashMap 在 0.75 时扩容），开放寻址法必须 α<0.75 甚至更低。**扩容 = 造一个更大的表，把全部元素重新哈希（rehash）**——均摊后每次操作仍 O(1)（对照 d01 均摊分析）。哈希函数的要求：**均匀分布、确定性、快速**；工程哈希用键的分布特性设计，密码学场景另用加密哈希（SHA-256 等）。

**一条铁律**：哈希表的键必须是**不可变的**——键存进去后再变，它的哈希值就变了，表里再也找不到它（对照语言教程：Python dict 键不可变、Java HashMap 可变键自残）。

## 3.2 字符串匹配：朴素法与 KMP

**朴素（暴力）匹配**：模式串 P 对准文本 T 的每个位置逐字符比，失配就整体右移一位重来。时间 O(n×m)——大部分时候够用，最坏（如 T=`aaaa…a`，P=`aaa…ab`）很惨。

**KMP 的思想**（不背 next 数组推导，抓思想）：**失配时，模式串自己已经"看过"的部分里藏着信息**——已匹配的后缀若与模式串前缀相同，可以把模式串大幅右滑而**文本指针不回退**：

```
T: a b a b a b c ...
P: a b a b d
        ↑ 在 d 处失配，前面已匹配 "abab"
"abab" 的最长相等前后缀是 "ab" → 模式串滑到让这两个 ab 对齐：
T: a b a b a b c
P:     a b a b d
        ↑ 直接从这里继续比，文本指针没有回退！
```

📐 **定义**：**next 数组（失败函数）**记录模式串每个位置之前的子串的**最长相等前后缀长度**，失配时模式串指针跳到 `next[j]` 继续比较。预处理 O(m)，匹配 O(n)，总 **O(n+m)**——文本指针永不回退是它的灵魂。应用：文本编辑器查找、病毒特征码匹配、字符串周期问题（`next[m]` 与 m 的关系判周期）。

更现代的清单： Boyer-Moore（从右往左比+坏字符启发，实测最快）、Rabin-Karp（哈希滚动窗口，多模式匹配）、字符串哈希（把子串变成数字比较）——日常开发多数直接用语言内置函数（其内部多是这类算法的优化版）。

## 易错点清单

1. 把哈希表的"期望 O(1)"当成"保证 O(1)"——最坏（全部冲突）退化 O(n)；实时系统要选树（红黑树，O(log n) 有保障，Java 的 ConcurrentHashMap 树化桶）；
2. 忘记"键不可变"：把可变对象当键后修改 → 值蒸发；
3. KMP 只背模板不懂"文本指针不回退"——next 数组手推时错一步全错，考试常考手算 `ababaa` 的 next。

## 自测题

1. 负载因子 0.75、1024 格的哈希表里约多少元素？什么时候扩容？（约 768 个；超过即扩）
2. 开放寻址法为什么删除要打墓碑？（防止截断后续键的探测链——墓碑=占位通知"这里曾有，继续找"）
3. 求 `abab` 的 next 数组。（0 0 1 2——最长相等前后缀：a=0, ab=0, aba=1, abab=2）

# d04 树：二叉树、遍历、BST、堆

> 本章目标：树是"一对多"关系的抽象（目录树、组织架构、DOM）。掌握二叉树遍历、二叉搜索树与堆——查询加速的三代主力。

---

## 4.1 树与二叉树

📌 **比喻**：公司的组织架构图——一个 CEO（根），下辖若干部门（子节点），每个部门再分小组；没有上司的是根，没有下属的是叶子。

📐 **定义**：**树是 n（n≥0）个节点的有限集合**，有且仅有一个**根**，其余节点分成 m 个互不相交的子树。术语：**度**（子节点数）、**叶子**（度 0）、**深度/高度**（层数）。重要结论：n 个节点的树有 **n−1 条边**。

**二叉树**：每个节点至多两个子节点（左/右有序，不可换位）。两种必背的特殊形态：

- **满二叉树**：每层都满（每节点两子）；
- **完全二叉树**：只允许**最后一层缺右侧**的节点——它是**堆和顺序存储二叉树的基础**（可用数组存：父 i → 子 2i+1, 2i+2，无指针开销）。

数量结论（常考）：n 个节点、深度 h 的关系——满二叉树第 i 层 2^(i−1) 个、h 层共 2^h − 1 个；**n 个节点二叉树高度至少 ⌈log₂(n+1)⌉**（一层塞满才最矮）；n 个节点能构成 Catalan 数 C(2n,n)/(n+1) 种不同二叉树。

## 4.2 四种遍历：三种 DFS + 一种 BFS

📌 **比喻**：参观一座庄园——**先序**是"进门先拍大厅再看各屋"（根最先）；**中序**是"先看左厢房、大厅居中、右厢房"（根居中）；**后序**是"看完所有屋最后离场"（根最后）；**层序**是"一层一层看"（BFS）。

📐 **定义**（递归三行）：**先序**根→左→右；**中序**左→根→右；**后序**左→右→根。**层序**用队列逐层出队入子（d02 队列回收）。

应用语义：中序遍历**二叉搜索树得到升序序列**（重要！）；后序适合**自底向上汇总**（目录大小统计、表达式求值）；先序适合**自顶向下复制/序列化**。已知**先序+中序可唯一重建二叉树**（先序首=根，中序里找根分左右），**后序+中序**同理；**先序+后序不能唯一**（无法区分左右子树）。

遍历的循环版（非递归）：用**显式栈**模拟递归栈——递归的本质就是隐式用栈（d02 应用回收）。

## 4.3 二叉搜索树 BST：会排队的树

📌 **比喻**：猜数字游戏的决策树——每猜一次，范围砍一半；树就是把"每次的选择路径"固化存储。

📐 **定义**：**BST（Binary Search Tree）**满足：**左子树所有节点 < 根 < 右子树所有节点**（递归成立）。查找/插入/删除的代价都是 **O(h)**（h=树高）。**中序遍历 = 升序输出**（性质自证）。

**退化问题**：按 1,2,3,…顺序插入，树退化成**链表**（h=n），查询 O(n)——有序输入是 BST 的天敌。**平衡二叉树**应运而生：**AVL 树**严格平衡（任意节点左右子树高度差 ≤1，失衡靠**旋转**修复：LL/RR/RL/LR 四种），查询稳定 O(log n) 但旋转频繁；**红黑树**放宽约束（近似平衡，用颜色规则保证 h ≤ 2log(n)），增删的综合性能更好——它是 Java HashMap 树化、Linux 内核调度器的选择。更进一步 **B/B+ 树**（多叉、矮胖、一节点一磁盘页）专为磁盘设计——数据库索引（MySQL InnoDB）用 B+ 树（数据都在叶子、叶子串成链表方便范围查询）。

一句话记住家族：**BST 定规则 → AVL 严平衡 → 红黑树松平衡 → B+ 树为磁盘而生**——每一代都是对上一代痛点的回应。

## 4.4 堆：会自动排序的优先级队列

📌 **比喻**：比赛晋级赛（锦标赛）——冠军在塔尖，但想知道"第二名"不需要重赛全部，只看冠军旁边一路。

📐 **定义**：**堆是完全二叉树**且满足**堆序性**：**大根堆**任一父 ≥ 子（堆顶=最大）；**小根堆**任一父 ≤ 子（堆顶=最小）。**用数组存储**（完全二叉树的福利）：父 i ↔ 子 2i+1, 2i+2。

核心操作（以大根堆为例）：

- **上浮（sift-up）**：插入后与父比、比父大就换——O(log n)；
- **下沉（sift-down）**：删除堆顶后把末尾元素放顶，与较大子交换下沉——O(log n)；
- **建堆**：从最后一个非叶节点倒序逐个下沉，**O(n)**（不是 n·log n！高度求和的技巧）；
- **堆排序**：反复"取堆顶 + 下沉"，原地、O(n log n)、不稳定。

**堆 = 优先级队列的标准实现**：取"当前最重要/最小的"而不排全部——Top K 问题（10 亿个数取最大 100 个：维护 100 大小的**小根堆**，比全排序省无数倍）、定时器（最近到期先触发）、Dijkstra 最短路（d05 回收）。

## 易错点清单

1. n 个节点二叉树边数答 n——是 **n−1**；
2. 完全二叉树判断只看"满不满"——正确标准是**与满二叉树按层编号后一一对应**；
3. 堆是"半排序"结构——**兄弟之间无序**（父≥子只保证纵向），取"第二大"不能直接拿根的某个孩子完事；
4. 平衡树手推旋转：失衡节点从**插入点向上第一个不平衡者**找起。

## 自测题

1. 先序 ABDECF、中序 DBEACF，重建这棵树。（根 A，中序分左 DBE 右 CF；左子树先序 BDE 根 B 左 D 右 E——树：A(B(D,E),C(,F))）
2. 为什么堆建堆是 O(n)？（自底向上下沉，第 i 层节点下沉代价 ≤ h−i，求和 Σ(n/2^i)·i = O(n)）

# d05 图：社交网络与导航

> 本章目标：图是最通用的结构（树是图的无环特例）。掌握存储、两种遍历、最短路、拓扑排序——"关系网"类问题的全套工具。

---

## 5.1 图与存储

📌 **比喻**：微信好友关系——人与人之间"谁加了谁"；地图——城市之间"哪条路多长"。**图（graph）= 顶点（人/城市）+ 边（关系/道路）**。

📐 **定义**：图 G = (V, E)。**无向图**（好友互相）/ **有向图**（关注单向）/ **带权图**（边上带距离/费用）。术语：**度**（连接边数，有向图分入度/出度）、**路径**、**连通**、**环**。

两种存储（选型第一问）：

| 存储         | 方式                          | 空间   | 查"i 和 j 相邻吗" | 适用                             |
| ------------ | ----------------------------- | ------ | ----------------- | -------------------------------- |
| **邻接矩阵** | n×n 二维数组 `g[i][j]=1/权重` | O(n²)  | **O(1)**          | 稠密图（边多）、小图             |
| **邻接表**   | 每个顶点挂一条邻居链表/数组   | O(n+e) | O(度)             | **稀疏图**（现实世界几乎都稀疏） |

延伸：十字链表（有向图两头索引）、边集数组（只存边列表，Kruskal 用）。

## 5.2 遍历：BFS 与 DFS

📌 **比喻**：找朋友借书。**BFS（广度优先）**：先问一圈所有直接好友（第 1 层），都没有再问好友的好友（第 2 层）——**波纹扩散，保底最短**；**DFS（深度优先）**：逮住一个好友链到底（朋友的朋友的朋友），走不通退回来换一条——**一条道走到黑，回头改道**。

📐 **定义**：

- **BFS**：**队列**驱动。起点入队 → 出队访问 → 未访问邻居依次入队 → 重复。按"层"推进，**无权图中 BFS 首次到达即最短路径**（层数=距离）。O(n+e)；
- **DFS**：**栈/递归**驱动。走到底 → 回溯换岔路。O(n+e)。适合"存在性"问题（有没有环、能不能到达）、拓扑排序、连通分量计数。

两者都要** visited 标记**防绕圈。选型：**问"最少几步"用 BFS；问"有没有/列出所有"用 DFS**。

## 5.3 最短路：Dijkstra 与朋友

**单源最短路**（一个起点到全部）：

- **Dijkstra**：**贪心 + 优先级队列（小根堆，d04 回收）**——每次把"当前距离最小的未确定点"定案，并用它**松弛**邻居（`dist[v] > dist[u] + w` 则更新）。**要求边权非负**。堆优化后 O((n+e)log n)。导航软件的核心之一；
- **Bellman-Ford**：允许**负权边**，逐边松弛 n−1 轮，O(n·e)；还能检测**负环**（第 n 轮仍在更新 = 有负环）。慢但全能；
- **Floyd**：**多源**全对最短路，动态规划思想，O(n³)，小图一把梭：`d[i][j] = min(d[i][j], d[i][k]+d[k][j])`（允许经过中转点 k 逐个放开）。

选型速记：**非负权单源 → Dijkstra+堆；有负权 → Bellman-Ford；全对 → Floyd（小图）**。

## 5.4 拓扑排序：选课顺序

📌 **比喻**：大学选课有先修要求（数据结构要学前导 C 语言）——排出一个"满足所有先修的上课顺序"。

📐 **定义**：**拓扑排序**对**有向无环图（DAG）**排出一个线性序列，使每条边都"从前往后"。**Kahn 算法（BFS 思想）**：反复摘取**入度为 0** 的节点（无先修的课），摘掉后把它的出边入度减 1，新出现的入度 0 节点继续摘。**应用**：编译依赖顺序、任务调度、构建系统（make）。**判环**：如果摘不完（剩余节点都有入度），图中有环——依赖成环（你等我我先等你）无法排课。

（另一个实现：DFS 逆后序——节点所有出边处理完再记录自己，最后倒序。）

## 5.5 应用全景与最小生成树

- **连通分量**：DFS/BFS 数轮数（每轮标亮一片）；
- **最小生成树 MST**（n 个顶点连成 n−1 条边的最小总权重树）：**Kruskal**（边排序 + **并查集**判环：逐条选不成环的最小边）、**Prim**（点扩张，类似 Dijkstra）——铺设电网/网线总长最短；
- **并查集（Union-Find）**：处理"哪些元素属于同一伙"，路径压缩 + 按秩合并近乎 O(1)——Kruskal、朋友圈问题的地基；
- **关键路径**：AOE 网找工期瓶颈（工程管理）。

## 易错点清单

1. BFS 忘 visited 标记 → 队列爆炸；DFS 递归深度大图爆栈（改显式栈或 BFS）；
2. Dijkstra 用在**负权图**上——结果可能错（它假设"定案即最优"，负边会翻案）；负权请 Bellman-Ford；
3. 拓扑排序对**无向图/有环图**无意义（有环用 Kahn 摘不完——这本身是判环手段）；
4. 邻接矩阵存稀疏图 → 内存爆炸（n=10⁵ 时 n²=10¹⁰ 格）。

## 自测题

1. 无权图最短路用什么？为什么？（BFS——按层推进，首次到达层数即最少步数）
2. Kahn 算法输出序列只有 5 个节点但图有 8 个节点，说明什么？（有环，3 个节点成环依赖）
3. Dijkstra + 堆的复杂度？与 Bellman-Ford 各适用什么场景？（O((n+e)log n)；非负权 vs 有负权/需判负环）

# d06 排序与算法思想

> 本章目标：八大排序一张表定乾坤（考点与面试双高频）；四种算法思想（贪心/分治/DP/回溯）用经典题各钉一遍。这是数据结构的收官章。

---

## 6.1 八大排序总表（背诵与查阅核心）

| 算法      | 平均           | 最坏           | 空间       | 稳定  | 思想     | 一句话                           |
| --------- | -------------- | -------------- | ---------- | ----- | -------- | -------------------------------- |
| 冒泡      | O(n²)          | O(n²)          | O(1)       | ✓     | 交换     | 相邻逆序两两换，大数冒泡到尾     |
| 选择      | O(n²)          | O(n²)          | O(1)       | ✗     | 选择     | 每轮选最小放前面                 |
| 插入      | O(n²)          | O(n²)          | O(1)       | ✓     | 插入     | 像理牌：新牌往有序区里插         |
| 希尔      | O(n^1.3)       | 取步长         | O(1)       | ✗     | 插入改进 | 分组粗排逐渐变细                 |
| 快排      | **O(n log n)** | **O(n²)**      | O(log n)栈 | ✗     | 分治     | 选基准分两半，递归两侧           |
| 归并      | **O(n log n)** | **O(n log n)** | **O(n)**   | **✓** | 分治     | 拆到最小再两两合并               |
| 堆排      | **O(n log n)** | O(n log n)     | O(1)       | ✗     | 选择改进 | 建堆反复取堆顶（d04）            |
| 计数/基数 | O(n+k)         | O(n+k)         | O(n+k)     | ✓     | 非比较   | 值域小直接计数（"押韵"不是比较） |

📌 **记忆比喻**：**冒泡**=气泡上浮；**选择**=每轮擂台选最矮站第一；**插入**=斗地主摸牌插入手牌；**快排**=按身高分两队再各自分队；**归并**=两组已整理的试卷合并成一份有序的。

三条高频结论：

1. **稳定性**（相等元素排序后保持原相对顺序）：**不稳定四兄弟 = 选择、快排、希尔、堆**（口诀"快些选堆"）；稳定的意义：多轮排序（先按部门再按工资）时上一轮不白排；
2. **快排最坏 O(n²)** 的触发条件：**基准选得极偏**（已有序数组选首元素）——随机取基准/三数取中规避；
3. **"N 个取最大 K 个"不要全排序**：小根堆 O(n log K) 或快速选择（快排只递归一侧，平均 O(n)）。

## 6.2 二分查找

📌 **比喻**：翻字典——翻开中间，决定扔左半还是右半。

📐 **定义**：在**有序**数组中，与中点比较，每次砍半，O(log n)。三要素：**有序、随机访问、边界处理**。变体：找第一个 ≥x（lower_bound）、找最后一个 ≤x、旋转数组找目标（先判断哪半有序）。**边界写错是重灾区**——统一用左闭右开或左闭右闭其一，注释每个边界含义（对照语言教程二分章 `lo + (hi-lo)/2` 防溢出）。**二分答案**进阶：若答案具有单调性（"容量 x 能否装下"随 x 单调），可对答案二分。

## 6.3 四大算法思想

**① 贪心（Greedy）**：每步取局部最优，期望全局最优。
📌 比喻：找零钱永远先给最大面额。
适用前提：**问题具有贪心选择性质**（局部最优能导出全局最优）——找零（币制 1/5/10/50）成立；反例：币制 1/3/4 找 6，贪心给 4+1+1（3 枚）而最优 3+3（2 枚）。经典：区间调度（按结束时间排序选最多不重叠区间）、Huffman 编码、Dijkstra（d05）。
**何时怀疑贪心失效**：当前选择会影响后面的选择余地时。

**② 分治（Divide & Conquer）**：拆成同型子问题 → 分别解 → 合并。
📌 比喻：班级大扫除分组干、最后合检查。
三段式：分解→解决（递归到可直接解）→合并。经典：归并排序、快排、二分、**大整数乘法**、**最近点对**。主定理粗算复杂度：T(n) = a·T(n/b) + f(n)（a 个子问题、规模 b 分之一）。

**③ 动态规划（DP）**：**记录子问题的解，避免重复计算**——适用于**重叠子问题 + 最优子结构**。
📌 比喻：爬楼梯的体力表——到第 n 级的最小体力 = min(到 n−1, 到 n−2) + 本级消耗，从第一级填表到第 n 级。
**模板四步**：① 定义状态（dp[i] 是什么）；② 状态转移方程；③ 初始化（边界）；④ 遍历顺序（保证算 dp[i] 时依赖项已算好）。经典题：斐波那契（朴素递归指数级 → DP 线性，对照语言教程）、最长公共子序列 LCS、0-1 背包（`dp[j] = max(dp[j], dp[j-w]+v)` 倒序循环）、最长上升子序列。
**DP vs 分治**：分治子问题**不重叠**（排序左右两半互不相干）；DP 子问题**大量重叠**（fib(5) 反复算 fib(3)）。
**DP vs 贪心**：贪心不回头；DP 全面比较——贪心快但可能错，DP 稳但费表。

**④ 回溯（Backtracking）**：**试探 + 撤销**——把所有可能当树来遍历（决策树 DFS），走不通退一步换岔路。
📌 比喻：迷宫里的粉笔——画线探路，死路擦掉回退。
模板：路径（当前选择）→ 选择列表 → 结束条件。三件套：**做选择 → 递归 → 撤销选择**。经典：全排列、N 皇后、子集/组合、数独。剪枝（提前判断必死分支直接跳过）是回溯的效率生命线。

## 6.4 算法思想选型速查

| 问题特征                                 | 首选思想    |
| ---------------------------------------- | ----------- |
| 每步局部最优即全局最优（硬币、区间调度） | 贪心        |
| 独立子问题可拆可并（排序、大数乘法）     | 分治        |
| 求最值/方案数 + 子问题重叠（背包、LCS）  | 动态规划    |
| 求所有方案/存在性（排列、迷宫、数独）    | 回溯 + 剪枝 |
| "最少几步"无权图                         | BFS         |
| 有序查找/答案单调                        | 二分        |

## 自测题

1. 为什么说"归并排序稳定且最坏 O(n log n)，但工程上快排更快"？（归并要 O(n) 辅助数组、拷贝开销大、缓存不友好；快排原地、缓存友好，配合随机基准实践中最坏罕见）
2. 0-1 背包为什么不能贪心"按单位价值高先拿"？（拿了大件可能堵死剩余容量——局部最优不保全局；反例可构造）
3. 求解 n 皇后用哪种思想？核心加速手段？（回溯；剪枝——同列/对角冲突提前剪枝）

## A.2 复杂度决策清单

1. n 多大？≤20 → 暴力/回溯随便；10⁵ → 必须 n log n 以内；10⁸ → O(n) 或 O(1)；
2. 数据有序吗？→ 有序二分；无序先想哈希；
3. 只要"有没有/第几大"？→ 哈希/堆（不排序）；
4. "最少几步"？→ 无权 BFS、有权 Dijkstra；
5. 求最值/方案数？→ 先想贪心（判断成立），不成立上 DP；
6. 列出所有方案？→ 回溯 + 剪枝。

## A.3 刷题路线（配套练习建议）

1. **线性**：双指针、滑动窗口、前缀和（数组的三大套路）；
2. **栈队列**：单调栈（下一个更大元素）、用栈实现队列；
3. **哈希**：两数之和、字母异位词分组；
4. **树**：遍历（递归/迭代各一遍）、最近公共祖先 LCA、层序锯齿遍历；
5. **堆**：TopK、中位数流（双堆：大根堆+小根堆对半分）；
6. **图**：岛屿数量（DFS 网格）、课程表（拓扑）、网络延迟（Dijkstra）；
7. **排序/思想**：手写快排与归并、背包三连（0-1/完全/分组）、LCS、全排列。

每题标准动作：**先口述思路 → 说复杂度 → 写代码 → 边界自测**——面试与训练同款流程。

## A.4 进阶路线

- **理论深化**：《算法导论》（严谨全集）、《算法 4》（Sedgewick，工程味浓）；
- **面试实战**：LeetCode 按标签刷（本附录 A.3 顺序）、《剑指 Offer》；
- **工程结合**：读语言标准库源码（Java HashMap/Python dict 的拉链实现、语言内置 sort 的混合排序策略）——把"课堂结构"与"工业实现"对上号；
- **高级专题**（按需）：并查集进阶、线段树/树状数组（区间统计）、字符串自动机（AC 自动机）、位运算技巧。

## A.5 四十句话全书浓缩（最终自测）

1. 数据结构 = 逻辑结构 + 存储结构；2. 大 O 只讲增长趋势；3. 均摊 = 偶发大代价摊平；4. 数组随机访问、链表就地增删；5. 栈 LIFO 管调用与回退；6. 队列 FIFO 管公平与 BFS；7. 循环队列牺牲一格判满；8. 哈希 = O(1) 的代价比是冲突；9. 拉链好删、开放寻址省内存；10. 键不可变；11. KMP 文本指针不回退；12. next = 最长相等前后缀；13. 树 n 节点 n−1 边；14. 中序遍历 BST 即升序；15. 有序输入毁 BST → 平衡树救场；16. B+ 树为磁盘而生；17. 堆 = 完全二叉树 + 堆序；18. 建堆 O(n)；19. TopK 用小根堆；20. 图 = 点+边；21. 稀疏用邻接表；22. BFS 队列波纹最短；23. DFS 栈深探；24. Dijkstra 拒绝负权；25. Kahn 摘不完 = 有环；26. Kruskal 并查集；27. 稳定排序保相对序；28. "快些选堆"不稳定；29. 快排最坏来自偏基准；30. 二分砍一半防溢出中点；31. 贪心要性质；32. 分治子问题不重叠；33. DP 子问题重叠 + 最优子结构；34. 回溯 = 试探 + 撤销 + 剪枝；35. 先想存再想算；36. 画图优先；37. 边界是 bug 重灾区；38. 缓存友好是隐藏性能；39. 复杂度在大 n 才说话；40. 结构选对，算法自现。

40 句全答得上来，数据结构与算法体系即成。
